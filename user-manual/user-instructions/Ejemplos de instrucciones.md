# Ejemplos de instrucciones

[Manual de usuario](<../Manual de usuario.md>)

Describa su objetivo en el idioma que prefiera.
Dé instrucciones claras a su agente en el entorno de ejecución de agentes elegido, tomando como guía los ejemplos siguientes.
Los ejemplos siguientes se agrupan en instrucciones de [configuración](#setup), [investigación](#research), [administración](#administration-instructions), [redacción de manuscritos](#writing-instructions) y [formalización en Lean](#lean-instructions).
Adapte la redacción a su pregunta, sus archivos y el alcance real del trabajo.

## <a id="setup"></a>Instrucciones de configuración

Utilice estos ejemplos para preparar su espacio de trabajo, registrar su identidad de autor y configurar los recursos locales.
Consulte la sección de [configuración](<../Manual de usuario.md#setup>) del manual para conocer el orden de los pasos de instalación y registro.

| Ejemplo de instrucción | Acciones esperadas del agente |
| --- | --- |
| <a id="install-acme"></a> Descargue e instale ACME (https://github.com/vtejdn/acme) en `D:\my-math-repository`. | Antes de la primera instalación, confirmar que la raíz local real del proyecto y cualquier repositorio remoto del proyecto seleccionado no contengan contenido ni historial del proyecto, salvo la configuración inicial de Git. Si algún destino ya está ocupado, conservarlo, detener esta instalación e indicar qué lado está ocupado. Solo tras confirmar que todos los destinos aplicables están vacíos, instalar los archivos de la versión oficial seleccionada en la raíz del proyecto sin los metadatos Git del repositorio oficial; completar la configuración necesaria, verificar la versión y los puntos de entrada, e informar de la ubicación, la versión y el trabajo pendiente. Una instalación ACME existente sigue el procedimiento de actualización autorizado; incorporarse a una colaboración implica clonar su repositorio real de investigación. |
| <a id="register"></a> Registre Ali como mi clave de autor; utilice Alice como nombre completo. | Tras comprobar la clave y los registros existentes, utilizar los valores proporcionados: `Ali` como clave de autor y `Alice` como nombre para la atribución de `LICENSE`. Registrarle, añadir la atribución conservando las identidades y los avisos existentes, y asociar esta copia de trabajo con `Ali` si utiliza Git. |
| <a id="install-git"></a> Instale [Git](<../git-repository/Repositorios Git.md#notion-git>). | Comprobar si Git ya está instalado, instalarlo si es necesario e informar de la versión disponible y de los pasos de configuración pendientes. |
| <a id="setup-git"></a> Establezca el nombre para los commits de Git de este repositorio en `Alice` y el correo electrónico en `alice@email.com`. | Comprobar la identidad de Git efectiva para los commits de este repositorio. Configurar el nombre y el correo electrónico proporcionados en el ámbito del repositorio o del árbol de trabajo cuando sea necesario. Verificar que coincidan con los datos de identidad Git registrados para el autor e informar de los valores efectivos. |
| Explíqueme cómo conectarme a [GitHub](<../git-repository/Repositorios Git.md#notion-github>). | Explicar cómo iniciar sesión, autenticarse y conectarse a un repositorio remoto, indicando los pasos que debe completar personalmente. |
| <a id="test-github-ssh"></a> Pruebe mi conexión SSH a GitHub. | Probar la autenticación con `ssh -T git@github.com` usando la configuración de SSH prevista para Git y sustituir el nombre del host por el alias configurado, si lo hay. Antes de aceptar una clave de host nueva, comprobar que su huella digital coincida con una de las publicadas por GitHub. Dar por correcta la autenticación si GitHub la confirma en su mensaje, aunque el código de salida sea `1`. Informar de la cuenta que aparece en el mensaje y de cualquier discrepancia con la cuenta esperada. Si la prueba falla, indicar el error concreto. [Guía de GitHub para probar la conexión SSH](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection) |
| He configurado la conexión a GitHub. Compruebe la conexión. | Identificar el repositorio de GitHub de destino y ejecutar `git ls-remote` mediante la conexión SSH o HTTPS configurada para comprobar el acceso de lectura. Si el repositorio está vacío, la comprobación puede tener éxito sin devolver referencias. Indicar el destino, el protocolo utilizado, la cuenta si se pudo verificar y el resultado de la lectura o el error concreto. [Referencia de Git para `ls-remote`](https://git-scm.com/docs/git-ls-remote) |
| <a id="setup-repo"></a> Establezca la clave del repositorio en `〈clave del repositorio〉`. | Validar la clave elegida, registrar un valor válido y actualizar las referencias actuales afectadas; pedirle otra elección si no es válida. La clave del repositorio es independiente de la abreviatura, el nombre completo y el título del README del proyecto; conservar el significado de las claves de autor, las identidades de los materiales y los datos históricos de procedencia. |
| Establezca la abreviatura y el nombre completo del repositorio en `〈abreviatura〉` y `〈nombre completo〉`. | Registrar la abreviatura y el nombre completo del proyecto elegidos por separado, comprobando que ambos sean texto no vacío de una sola línea. Utilizarlos para formar el encabezado principal del README «〈abreviatura〉: 〈nombre completo〉», mantener la coherencia entre la configuración y el título y conservar el resto del texto. La clave del repositorio se establece por separado. |
| <a id="connect-github"></a> Configure Git y conéctelo a mi repositorio <https://github.com/alice/acme>. | Inicializar Git solo si es necesario, completar los registros pendientes del nombre del repositorio o del autor según sus elecciones y asociar la copia de trabajo con su clave de autor. Comprobar o configurar la identidad de los commits para que coincida con su registro, conectar el repositorio remoto indicado y probar el acceso mediante la cuenta o el canal de autenticación pertinente. Conservar los commits existentes, la configuración ajena al encargo y los límites de los Tasks, e informar del destino configurado y de los pasos de configuración pendientes. |
| <a id="clone-repo"></a> [Clone](<../Manual de usuario.md#notion-clone>) el repositorio de mi colaborador <https://github.com/alice/acme> y regístreme como Bob. | Clonar el repositorio compartido y comprobar la clave de autor `Bob`, su identidad real y los registros existentes. En un primer registro, preguntar antes por el nombre de atribución de `LICENSE` elegido de forma independiente y después registrar al autor y añadir el aviso necesario. Reutilizar una identidad existente aplicable, asociar la nueva copia de trabajo Git con la clave verificada, conservar los autores y materiales de investigación existentes y explicar la configuración de identidad de los commits de Git. |

| Ejemplo de instrucción | Acciones esperadas del agente |
| --- | --- |
| <a id="commit"></a>Cree un commit de todos los cambios del espacio de trabajo. | Comprobar todos los cambios del espacio de trabajo y su autoría, crear un commit local del contenido que deba guardarse en Git, conservar los archivos excluidos por las reglas de exclusión e informar del alcance del commit y de los cambios restantes. |
| <a id="commit-push"></a>Cree un commit y haga push. | Determinar el alcance de la entrega prevista y conservar los cambios ajenos ya preparados en el área de staging. Comprobar la identidad del autor de los cambios, la rama y el repositorio remoto de destino; confirmar la conexión, crear el commit y hacer push, e informar del alcance incluido en el commit y del resultado remoto. |
| Cree un commit y haga push de los cambios del directorio del manuscrito de F0001. | Localizar el proyecto de manuscrito de F0001, incluir en el commit solo los cambios del directorio indicado que deban guardarse en Git y conservar el resto del trabajo. | Cree un commit y haga push sin ninguna comprobación. | Omitir la revisión del contenido, las comprobaciones de formato, las pruebas y las exploraciones adicionales. Realizar solo las comprobaciones de alcance, identidad, destino y conexión necesarias para la entrega mediante Git; después crear el commit, hacer push e informar del resultado. |
