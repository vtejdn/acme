## <a id="setup"></a>セットアップの指示

これらの例は、作業環境の準備、著者の登録、ローカル資源の設定に使います。
インストールと登録の手順は、マニュアルの[セットアップ](../ユーザーマニュアル.md#setup)を参照してください。

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| ACME (https://github.com/vtejdn/acme) を `D:\my-math-repository` にダウンロードしてインストールしてください。 | 指定ディレクトリの既存の内容を確認し、選択した公式バージョンのフレームワークファイルを実際のプロジェクトルートに統合します。既存の内容と Git 履歴を保持し、公式リポジトリの Git メタデータは取り込みません。既存のプロジェクト情報と著者情報を再利用して必要な設定を補い、ルートにあるフレームワークのバージョンと入口を確認し、実際のインストール先、バージョン、未完了事項を報告します。 |
| [Git](../git-repository.md#notion-git) をインストールしてください。 | Git がインストール済みかを確認し、必要ならインストールして、利用できるバージョンと今後必要な設定を報告します。 |
| Ali を私の著者キーとして登録し、氏名には Alice を使ってください。 | キーと既存の登録を確認し、指定された `Ali` を著者キー、`Alice` を `LICENSE` の著者表示名として使います。既存の識別情報と通知を保持して著者登録と著者表示の追加を行い、この作業コピーが Git を使う場合は `Ali` に関連付けます。 |
| [GitHub](../git-repository.md#notion-github) に接続する方法を教えてください。 | ログイン、認証、リモートリポジトリへの接続手順を説明し、利用者自身が行う必要のある操作を示します。 |
| GitHub への SSH 接続をテストしてください。 | Git で使う SSH 設定で `ssh -T git@github.com` を実行し、認証を確認します。SSH のホスト別名が設定されている場合は、その別名を使います。新しいホスト鍵を受け入れる前に、そのフィンガープリントが GitHub の公開値と一致することを確認します。GitHub が認証成功を示すメッセージを返した場合は、終了コードが `1` でも認証成功と判断します。表示されたアカウントを報告し、想定していたアカウントと異なる場合はその旨も伝えます。失敗した場合は、具体的なエラーを報告します。 [GitHub の SSH 接続テストガイド](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection) |
| GitHub への接続を設定しました。接続をテストしてください。 | 対象の GitHub リポジトリを特定し、設定済みの SSH または HTTPS 接続で `git ls-remote` を実行して読み取りアクセスを確認します。空のリポジトリでは、読み取りに成功しても参照が返らないことがあります。接続先と使用したプロトコル、確認できた場合はアカウントを報告し、読み取りの結果または具体的なエラーを伝えます。 [Git の `ls-remote` リファレンス](https://git-scm.com/docs/git-ls-remote) |
| リポジトリキーを`〈リポジトリキー〉`に設定してください。 | 選んだリポジトリキーを検証し、有効な値を記録して影響する現在の参照を更新します。無効な場合は別の値を選ぶよう依頼します。リポジトリキーはプロジェクトの略称、正式名称、README のタイトルとは別の設定であり、著者キー、資料の識別情報、過去の出典情報の意味を保持します。 |
| リポジトリの略称と正式名称を`〈略称〉`、`〈正式名称〉`に設定してください。 | それぞれ選択されたプロジェクトの略称と正式名称が、空でない一行の文字列であることを確認して記録します。この二つから README の主見出しを「〈略称〉: 〈正式名称〉」とし、設定と見出しを一致させ、残りの本文を保持します。リポジトリキーはこれらとは別に設定します。 |
| Git を設定し、私のリポジトリ <https://github.com/alice/acme> に接続してください。 | 必要な場合にのみ Git を初期化し、指定された内容に従って未登録のリポジトリ名や著者情報を登録して、作業コピーを自分の著者キーに関連付けます。コミットの識別情報が登録と一致するよう確認または設定し、指定されたリモートに接続して、該当するアカウントまたは認証経路でアクセスをテストします。既存のコミット、無関係な設定、Task の制限を保持し、設定した接続先と残る設定手順を報告します。 |
| 共同研究者のリポジトリ <https://github.com/alice/acme> を[クローン](../ユーザーマニュアル.md#notion-clone)し、私を Bob として登録してください。 | 共有リポジトリをクローンし、著者キー `Bob`、実際の利用者、既存の登録を確認します。初回登録では、独立して選ぶ `LICENSE` の著者表示名を先に尋ねてから、登録と必要な著者表示の追加を行います。適用できる既存の登録を再利用し、新しい Git 作業コピーを確認済みの著者キーに関連付け、既存の著者と研究資料を保持して、Git のコミットに使う識別情報の設定状況を説明します。 |

## <a id="research-instructions"></a>研究の指示

これらの例は、文献の扱いと数学的探究に使います。

### 文献を検索・登録・検証する

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| ローカル文献 abc26 を確認し、登録して検証してください。 | abc26 の文献、版、ローカルの原本を確認し、書誌情報を補い、必要に応じて版と原本の所在に関する注記を整えます。原本に目次がある場合は、検索可能な文献目次を作成します。数学的内容を検証し、実際に確認した範囲、結論、未解決の問題を記録します。 |
| 文献 abc26 の定理 1.7 を検証してください。 | 原本の定理 1.7 を特定し、完全な主張、仮定、証明、必要な前提となる結果の適用可能性を確認します。検証の所見、未確認の部分、具体的な欠落を記録します。 |
| On the construction of S を検索し、登録と検証を試みてください。 | 文献と版を特定し、既存資料を調べて原本の取得を試みます。書誌情報を補い、必要に応じて取得した版と出典の所在に関する注記を整えます。原本に目次がある場合は、検索可能な文献目次を作成します。取得した内容を検証し、取得の失敗、利用できない部分、実際の確認範囲を報告します。 |
| この定義は、関連文献でどのように使われていますか。 | 既存の定義記録と関連する原本を調べ、対象、仮定、記号、使用場面を比較し、正確な引用を示します。出典の定義と、ローカルでの書き換えや一般化を区別します。 |

### <a id="start-or-continue-research"></a>[研究課題](../ユーザーマニュアル.md#material-task)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| abc26 の予想 1.3 を、[W ライン](../ユーザーマニュアル.md#notion-research-line-letter)の Task として設定してください。 | 予想 1.3 の原文、仮定、範囲を確認し、同じ問いの既存 Task を先に探します。新設が必要な場合は W ラインを使い、出典、正確な問い、完了基準を記載します。 |
| 「P ならば Q」を目標として、F ラインの Task を設定してください。 | P と Q の対象、仮定、量化を明確にし、「P から Q が導かれる」ことを目標の全体として F ラインの Task を作成し、完了基準を明示します。 |
| 命題 P を有限次元の場合から無限次元の場合へ一般化する、新しい Task を作成してください。 | 元の命題を確認し、新しい対象、仮定、目指す結論を明確にして Task を作成します。元の命題を、一般化が含むべき特殊例として保持します。 |
| P の状況で abc26 の式 (1) を含む一般公式を見つける Task を設定してください。 | 元の式の仮定と記法を確認し、P の状況と一般公式の適用範囲を明確にします。Task を作成し、正しい導出と、元の式をどのように含むかの説明を完了基準に記載します。 |
| Task F0001 を、週間利用枠の残りが 5% になるまで進めてください。 | Task の現状と有効な実行条件を確認し、対象アカウントの週間利用量を取得できることを確かめます。取得できない場合は制限を説明し、進行を見合わせます。実行条件を満たしてから研究を進め、残量を監視し、残りが 5% 以下になったことを最初に観測した時点、または監視が失敗した時点で停止します。有用な結果、未解決の問い、再開箇所を保持し、有効な停止条件を記録します。 |
| 現在の進捗を整理してから、一時停止してください。 | 現在のラウンドの確認と整理を終え、有益な結果、失敗した試行、残る問い、再開できる箇所を保存します。一時停止と引き続き有効な条件を記録し、それ以上の進行を止めます。 |
| F0001 の現在の進捗を報告してください。 | Task の現状を確認し、証明済みの結果、候補となる議論、計算による観察、未解決の問いを区別します。関連資料へのリンクを示し、当初の目標に到達するために不足しているものを説明します。 |
| Task F0001 を続けてください。 | 現在の目標、戦略、既存の成果、停止条件を読み、今回の許可と引き続き有効な制限のもとで再開します。解除されていない停止条件がある場合は、継続を妨げている具体的な理由を説明します。 |

### [研究戦略](../ユーザーマニュアル.md#material-strategy)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| 理論 A を使って S を構成することを検討できます。この戦略を[研究課題](../ユーザーマニュアル.md#material-task) F0001 に加えてください。 | 理論 A の適用可能性を確認し、候補となる構成を F0001 の研究戦略として整理します。仮定、期待する役割、未検証の段階、次の手順を説明し、既存の戦略と比較して重複を避けます。 |
| 上の議論を F0001 の戦略にまとめてください。 | 議論に対応する研究の仕組みを特定し、既存の戦略を更新するか、必要に応じて新しい戦略を作成します。根拠、未解決の問い、次の手順を保持し、F0001 に関連付けます。 |
| Task G0001 のために検索・分析し、戦略を提案して優先順位を自律的に決めてください。 | G0001 の目標、制約、既存の戦略と関連資料を読み、まずローカルの成果を再利用したうえで、必要に応じて文献を検索・検証します。候補となる方針の適用条件、根拠、障害、必要な資源を比較し、戦略を提案し、優先順位を自律的に決めます。順位の理由、未解決の段階、次の手順を記録し、元の目標、完了基準、有効な実行制限を保持します。 |

### [共同研究課題](../ユーザーマニュアル.md#material-task)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| まず共同研究者 Alice の方針を調べ、私の Task F0001 に有用な方法を選んでください。 | 関連する方針、再利用できる成果、示唆に富む失敗を読み、F0001 の参加範囲と既存の実行条件の中で自分の Strategy を選択または調整します。異なる方針は作業の重複を減らせますが、意図的な独立検証、再現、相互確認も適切です。 |
| この問題について共同 Task を設け、Task F0001 に関連付けてください。 | 共通の問題、仮定、範囲、完了基準を確認し、適切な共同 Task を作成または再利用したうえで、あなたの F0001 を実際に採用した共通契約の版に関連付け、参加範囲と個人の完了基準を明確にして、既存の実行条件を保持します。関連付けだけでは研究を開始しません。 |

## <a id="administration-instructions"></a>管理の指示

これらの例は、[Git](../git-repository.md#notion-git) 操作、環境設定、日常的な保守に使います。

### [コミット](../ユーザーマニュアル.md#notion-commit)と[プッシュ](../ユーザーマニュアル.md#notion-push)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| コミットして、プッシュしてください。 | 今回の提出範囲を定め、他のステージ済み作業を保持し、実際の識別情報、ブランチ、対象リモートを確認します。接続を確認したうえでコミットを作成してプッシュし、コミットの範囲とリモートでの結果を報告します。 |
| F0001 に対応する原稿ディレクトリ内の変更をコミットして、プッシュしてください。 | F0001 に対応する原稿プロジェクトを特定し、指定ディレクトリ内で Git に含めるべき変更だけをコミットし、他の作業を保持します。識別情報、対象、接続を確認してからプッシュし、実際の範囲を報告します。 |
| 作業領域の変更をすべてコミットしてください。 | 作業領域内のすべての変更と著者の帰属を確認し、Git に含めるべき内容をローカルにコミットします。無視ルールで除外されたファイルはそのまま保存し、コミットの範囲と残る変更を報告します。 |
| 確認作業をせず、コミットしてプッシュしてください。 | 内容の検証、書式確認、テスト、追加の走査は行いません。Git による提出に必要な範囲、識別情報、対象、接続の確認だけを行い、指定されたコミットとプッシュを完了して結果を報告します。 |

### [プル](../ユーザーマニュアル.md#notion-pull)と[マージ](../ユーザーマニュアル.md#notion-merge)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| リモートの最新の変更をプルし、[ローカルブランチ](../ユーザーマニュアル.md#notion-git-branch)にマージしてください。 | 現在のブランチと対応するリモートを確認し、ローカルの作業を保持して、リモートの更新を取得・統合し、結果を報告します。数学的な意味に関わる競合がある場合は、具体的な違いと対応案を説明します。 |

### 環境設定

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| ディレクトリジャンクション（Junction）を作成し、[mathematics/literature/pdf](../../mathematics/literature/pdf) を `D:\MyLiterature` へ向けてください。 | プロジェクト内の入口パスと保存先ディレクトリを確認し、既存の文献を保持して、ローカル文献の入口を指定ディレクトリへの Junction に設定します。文献ファイルが Git に含まれないことも確認します。 |
| このプロジェクトで使う`〈harness 名〉`の既定の[コンテキスト長](../ユーザーマニュアル.md#notion-context-length)を 512k にしてください。 | その [harness](../agent-harness.md) のプロジェクト単位の設定を調べ、モデルと実行環境が指定の長さに対応することを確認してから、このプロジェクトの既定値を変更します。反映方法と、実際に反映されたことを検証済みかどうかを説明します。対応していない場合は、実際の制限を報告します。 |
| Task の既定の停止条件を、週間利用枠の残りが 5% の時点で一時停止するように設定してください。 | より具体的な設定が優先されない場合に適用する、個人の既定の実行設定として記録します。既存 Task の有効な条件は保持し、該当する週間利用量を取得する方法を説明します。 |

### [取り込み](../ユーザーマニュアル.md#notion-import)と[受け入れ](../ユーザーマニュアル.md#notion-intake)

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| 私のリポジトリ`〈リポジトリURL〉`から Task F0001 を取り込んでください。 | 元のリポジトリとあなたの著者情報を確認し、F0001 と必要な数学的依存資料を取り込み、十分な既存のローカル資料を再利用します。必要な他の著者の資料は Intake で受け入れ、状況に応じて共通契約との関連付けを保持するか、完全な独立契約を整えます。有効な停止条件と利用枠を保持し、取り込みだけでは研究を開始しません。 |
| 私のリポジトリ`〈リポジトリURL〉`から、私の執筆設定と原稿 F0001 を取り込んでください。 | 選択した個人の執筆設定のうち現在も適用できるものと、原稿 F0001 のソースファイル、図、書誌、必要な数学的根拠を取り込みます。著者への帰属と設定の適用範囲を保持し、既存のローカル資料を再利用して参照を修正し、必要なコンパイル確認を行い、不足する入力と残る問題を説明します。 |
| `〈リポジトリURL〉`から、Alice の Task A0001 に関連する資料を受け入れてください。 | 元のリポジトリと Alice の著者情報を確認し、A0001 に関連する結果、論証、計算、検証のうち今回必要なものを選び、十分な既存資料を再利用します。受け入れ時には元の著者への帰属、正確な出典、必要な数学全体、実際の検証の限界を保持し、取得できなかった必要入力を報告します。その後の研究は、あなた自身の Task と許可の範囲内で進めます。 |

### 日常的な保守

| 指示例 | エージェントに期待される行動 |

| このリポジトリのフレームワークの自動バージョン確認を有効／無効にしてください。 | 有効化または無効化の選択に従ってこのリポジトリの設定を更新し、他の設定を保持して現在の設定状態を報告します。有効な場合は、UTC の各日について定められた自動確認のルールを適用します。アップグレードには引き続き実際の明示的な許可が必要です。 |
| フレームワークを最新バージョンにアップグレードしてください。 | インストール済みのバージョンと公式の最新バージョンを確認し、更新がある場合は対象バージョンとコミットを固定します。アップグレードの説明に従って影響するファイルを適合させ、必要な確認を行い、ローカルの変更、研究資料、個人設定、有効な実行条件を保持します。確認に合格してからインストール済みのバージョン情報を更新します。実際に複数の著者が共有する Git リポジトリでは、既定の許可に従ってコミット、プッシュ、リモート結果の確認を行い、ローカル作業のみ、オフライン、プッシュ禁止などの明示的な制限を守ります。変更前後のバージョン、対象コミット、確認と提出の結果、更新がない場合や未完了の事項を報告します。 |
| フレームワークのルールに従ってマージの競合を解決してください。 | 双方の変更、著者の帰属、実際の権限を確認し、対象と数学的意味を保つ参照先の修正を含め、判断できる管理上の競合を直接解決します。実質的な数学上の相違については双方の根拠を保持して違いを説明し、既存の許可に基づくか、必要な許可を得てから範囲を限定して再検証します。他の著者の内容に対する実質的な修正は、修正者自身の資料に保存します。マージ結果と影響する参照を確認し、処理結果と未解決事項を報告します。 |
| `.tmp` 内のファイルを調べ、安全に削除できるものを削除してください。 | ファイルの用途と使用状況を確認し、正式な研究資料にまだ保存されていない必要な内容を先に保全します。その後、廃棄可能で、他のアクティブな会話が使っていないと確認できた一時ファイルを削除します。 |
| ローカルの数学資料がフレームワークの規範に適合するか確認してください。 | 今回の範囲について、同じ範囲の修復・検収を担当するエージェントとは別の、他段階の実質的な議論を引き継がないエージェントが、ローカルの数学資料と必要な入力・参照を分割して読み取り専用で確認します。著者、版、評価、出典、検証と対象資料の対応などが現行ルールに適合するかを確認します。規範上の問題を `maintenance`、実質的な数学上の問題を `erratum` に記載し、実際の確認範囲、未確認の範囲、未解決事項を報告します。 |
| maintenance と erratum を読み、フレームワークのルールに従って修復してください。 | 今回の範囲で修復待ちの項目を読み、同じ範囲の確認・検収を担当するエージェントとは別の、他段階の実質的な議論を引き継がないエージェントが問題を確かめ、各著者の資料に対する実際の編集権限内で修復、自己点検、必要な依存資料の確認を行います。規範上の修復は独立したエージェントの検収を受け、数学上の誤りは実際に適用される版、評価、数学的検証の要件に従って扱います。元の問題、根拠、検収要件、未修復・未検収の項目を保持し、修復範囲と残る制限を報告します。 |
| フレームワークのルールに従って資料の修復を検収してください。 | 同じ範囲の確認や修復に参加せず、関連する実質的な議論も引き継いでいない独立したエージェントが、元の問題と現行ルールに照らし、検収待ちの修復と必要な依存資料を確認して、合格・不合格の範囲を報告します。著者側または受け入れ側の実際の処理権限内で項目の検収済み部分を整理し、不合格、未検収、範囲外、同時に追加された項目を保持します。検収段階では資料を修復せず、規範上の検収を数学的な独立検証と同一視しません。 |
