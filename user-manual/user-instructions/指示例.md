## <a id="setup"></a>セットアップの指示

これらの例は、作業環境の準備、著者の登録、ローカル資源の設定に使います。
インストールと登録の手順は、マニュアルの[セットアップ](../ユーザーマニュアル.md#setup)を参照してください。

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| [ACME](https://github.com/vtejdn/acme) を `D:\acme` にダウンロードしてください。 | 保存先がインストールに適しているかを確認し、ACME フレームワークのファイルをダウンロードし、既存の内容を保存して、実際のバージョンと今後必要な設定を報告します。 |
| [Git](../git-repository.md#notion-git) をインストールしてください。 | Git がインストール済みかを確認し、必要ならインストールして、利用できるバージョンと今後必要な設定を報告します。 |
| [GitHub](../git-repository.md#notion-github) に接続する方法を教えてください。 | ログイン、認証、リモートリポジトリへの接続手順を説明し、利用者自身が行う必要のある操作を示します。 |
| GitHub にログイン済みです。接続をテストしてください。 | 現在認証されているアカウントを確認し、読み取り専用で GitHub と対象リポジトリへの接続をテストして、結果または具体的なエラーを報告します。 |
| [ACME](https://github.com/vtejdn/acme) を `D:\acme` に[クローン](../ユーザーマニュアル.md#notion-clone)してください。 | Git、アクセス権、保存先が利用可能かを確認し、ACME リポジトリをバージョン履歴ごとクローンして、実際のブランチ、バージョン、今後必要な初期設定を報告します。 |
| 私を Ali として登録してください。 | 著者キー Ali を登録し、現在のディレクトリが Git の作業コピーなら同時に Ali に関連付けます。既存の協働者の識別情報は保持します。 |
| Git を設定し、私のリポジトリ <https://github.com/alice/acme> に接続してください。 | このプロジェクトの Git と指定されたリモートを設定し、実際のコミットの識別情報を確認してアクセスをテストします。既存のコミットと無関係な設定は保持します。 |
| 共同研究者のリポジトリ <https://github.com/alice/acme> をクローンし、私を Bob として登録してください。 | 共有リポジトリをクローンし、実際の利用者に対応する著者キー Bob を登録して、新しい Git 作業コピーを Bob に関連付けます。既存の著者と研究資料を保存し、Git のコミットに使う識別情報の設定状況を説明します。 |

## <a id="research-instructions"></a>研究の指示

これらの例は、文献の扱いと数学的探究に使います。

### 文献を検索・登録・検証する

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| ローカル文献 abc26 を確認し、登録して検証してください。 | abc26 の文献、版、ローカルの原本を確認し、書誌情報とファイルの登録を整えます。原本に目次がある場合は、検索可能な文献目次を作成します。数学的な内容を検証し、実際に確認した範囲、結論、未解決の問題を記録します。 |
| 文献 abc26 の定理 1.7 を検証してください。 | 原本の定理 1.7 を特定し、完全な主張、仮定、証明、必要な前提となる結果の適用可能性を確認します。検証の所見、未確認の部分、具体的な欠落を記録します。 |
| On the construction of S を検索し、登録と検証を試みてください。 | 文献と版を特定し、既存の記録を検索して原本の取得を試みます。書誌情報と実際の取得結果を登録します。原本に目次がある場合は、検索可能な文献目次を作成します。取得できた内容を検証し、利用できない部分を明示します。 |
| この定義は、関連文献でどのように使われていますか。 | 既存の定義記録と関連する原本を調べ、対象、仮定、記号、使用場面を比較し、正確な引用を示します。出典の定義と、ローカルでの書き換えや一般化を区別します。 |

### <a id="start-or-continue-research"></a>[研究課題](../ユーザーマニュアル.md#material-task)を開始・継続する

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| abc26 の予想 1.3 を、W ラインの Task として設定してください。 | 予想 1.3 の原文、仮定、範囲を確認し、同じ問いの既存 Task を先に探します。新設が必要な場合は [W ライン](../ユーザーマニュアル.md#notion-research-line-letter)を使い、出典、正確な問い、完了基準を記載します。 |
| 「P ならば Q」を目標として、F ラインの Task を設定してください。 | P と Q の対象、仮定、量化を明確にし、「P から Q が導かれる」ことを目標の全体として F ラインの Task を作成し、完了基準を明示します。 |
| 命題 P を有限次元の場合から無限次元の場合へ一般化する、新しい Task を作成してください。 | 元の命題を確認し、新しい対象、仮定、目指す結論を明確にして Task を作成します。元の命題を、一般化が含むべき特殊例として保持します。 |
| P の状況で abc26 の式 (1) を含む一般公式を見つける Task を設定してください。 | 元の式の仮定と記法を確認し、P の状況と一般公式の適用範囲を明確にします。Task を作成し、正しい導出と、元の式をどのように含むかの説明を完了基準に記載します。 |
| Task F0001 を進め、週間利用枠の残りが 5% になったら、進捗を整理して一時停止してください。 | Task の現状と実行条件を確認し、該当する週間利用量を取得できることを確かめてから研究を進めます。残量を監視し、5% の基準で進行を止め、成果、未解決の問い、再開箇所を整理して一時停止します。 |
| Task F0001 を続けてください。 | 現在の目標、戦略、既存の成果、停止条件を読み、今回の許可と引き続き有効な制限のもとで再開します。解除されていない停止条件がある場合は、継続を妨げている具体的な理由を説明します。 |

### 共通目標

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| まず共同研究者の方針を調べ、私の Task F0001 に有用な方法を選んでください。 | 関連する方針、再利用できる成果、示唆に富む失敗を読み、F0001 の参加範囲と既存の実行条件の中で自分の Strategy を選択または調整します。異なる方針は作業の重複を減らせますが、意図的な独立検証、再現、相互確認も適切です。 |
| この問題について共同 Task を設け、Task F0001 に関連付けてください。 | 共通の問題、仮定、範囲、完了基準を確認し、適切な共同 Task を作成または再利用したうえで、あなたの F0001 を実際に採用した共通契約の版に関連付け、参加範囲と個人の完了基準を明確にして、既存の実行条件を保持します。関連付けだけでは研究を開始しません。 |


### 内容の取り込み

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| 私のリポジトリ`〈リポジトリURL〉`から Task F0001 を取り込んでください。 | 元のリポジトリと、あなたが F0001 の著者であることを確認し、F0001 と必要な数学的依存資料を取り込み、十分な既存のローカル資料を再利用します。必要な他の著者の資料は Intake で受け入れ、状況に応じて共通契約との関連付けを保持するか、完全な独立契約を整えます。有効な停止条件と利用枠を保持し、取り込みだけでは研究を開始しません。 |
| 私のリポジトリ`〈リポジトリURL〉`から、私の執筆設定と原稿 F0001 を取り込んでください。 | 選択した個人の執筆設定のうち現在も適用できるものと、原稿 F0001 のソースファイル、図、書誌、必要な数学的根拠を取り込みます。著者への帰属と設定の適用範囲を保持し、既存のローカル資料を再利用して参照を修正し、必要なコンパイル確認を行い、不足する入力と残る問題を説明します。 |
| `〈リポジトリURL〉`から、Alice の Task A0001 に関連する資料を受け入れてください。 | 元のリポジトリと Alice の著者情報を確認し、A0001 に関連する結果、論証、計算、検証のうち今回必要なものを選び、十分な既存資料を再利用します。受け入れ時には元の著者への帰属、正確な出典、必要な数学全体、実際の検証の限界を保持し、取得できなかった必要入力を報告します。その後の研究は、あなた自身の Task と許可の範囲内で進めます。 |

## <a id="administration-instructions"></a>管理の指示

これらの例は、Git 操作、環境設定、日常的な保守に使います。

### コミットとプッシュ

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| [コミット](../ユーザーマニュアル.md#notion-commit)して、[プッシュ](../ユーザーマニュアル.md#notion-push)してください。 | 今回の提出範囲を定め、他のステージ済み作業を保持し、実際の識別情報、ブランチ、対象リモートを確認します。接続を確認したうえでコミットを作成してプッシュし、コミットの範囲とリモートでの結果を報告します。 |
| F0001 に対応する原稿ディレクトリ内の変更をコミットして、プッシュしてください。 | F0001 に対応する原稿プロジェクトを特定し、指定ディレクトリ内で Git に含めるべき変更だけをコミットし、他の作業を保持します。識別情報、対象、接続を確認してからプッシュし、実際の範囲を報告します。 |
| 作業領域の変更をすべてコミットしてください。 | 作業領域内のすべての変更と著者の帰属を確認し、Git に含めるべき内容をローカルにコミットします。無視ルールで除外されたファイルはそのまま保存し、コミットの範囲と残る変更を報告します。 |
| 確認作業をせず、コミットしてプッシュしてください。 | 内容の検証、書式確認、テスト、追加の走査は行いません。Git による提出に必要な範囲、識別情報、対象、接続の確認だけを行い、指定されたコミットとプッシュを完了して結果を報告します。 |

### プルとマージ

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| リモートの最新の変更を[プル](../ユーザーマニュアル.md#notion-pull)し、[ローカルブランチ](../ユーザーマニュアル.md#notion-git-branch)に[マージ](../ユーザーマニュアル.md#notion-merge)してください。 | 現在のブランチと対応するリモートを確認し、ローカルの作業を保持して、リモートの更新を取得・統合し、結果を報告します。数学的な意味に関わる競合がある場合は、具体的な違いと対応案を説明します。 |

### 環境設定

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| ディレクトリジャンクション（Junction）を作成し、[mathematics/literature/pdf](../../mathematics/literature/pdf) を `D:\MyLiterature` へ向けてください。 | プロジェクト内の入口パスと保存先ディレクトリを確認し、既存の文献を保持して、ローカル文献の入口を指定ディレクトリへの Junction に設定します。文献ファイルが Git に含まれないことも確認します。 |
| このプロジェクトで使う`〈harness 名〉`の既定の[コンテキスト長](../ユーザーマニュアル.md#notion-context-length)を 512k にしてください。 | その [harness](../agent-harness.md) のプロジェクト単位の設定を調べ、モデルと実行環境が指定の長さに対応することを確認してから、このプロジェクトの既定値を変更します。反映方法と、実際に反映されたことを検証済みかどうかを説明します。対応していない場合は、実際の制限を報告します。 |
| Task の既定の停止条件を、週間利用枠の残りが 5% の時点で一時停止するように設定してください。 | より具体的な設定が優先されない場合に適用する、個人の既定の実行設定として記録します。既存 Task の有効な条件は保持し、該当する週間利用量を取得する方法を説明します。 |

### 日常的な保守

| 指示例 | エージェントに期待される行動 |
| --- | --- |
| フレームワークのアップグレードを後回しにして、現在の作業を続けてください。 | インストール済みのバージョンを維持し、許可された作業を続けます。通知だけではアップグレードの許可にはなりません。 |
| このリポジトリのフレームワークの自動バージョン確認を無効にしてください。 | 現在のフレームワークと研究作業を保ったまま、このリポジトリの毎日のバージョン情報確認を無効にします。 |
| このリポジトリのフレームワークの自動バージョン確認を有効にしてください。 | リポジトリの毎日の確認を有効にします。その後のアップグレードには引き続き明示的な指示が必要です。 |
| 公式フレームワークのバージョンを今すぐ再確認してください。 | 制限時間のある新しい確認を一回行い、インストール済みのバージョンと確認できた利用可能なバージョン、または確認できなかった旨を報告し、既に行った通知の記録を保持します。 |
| 今確認した公式フレームワークのバージョンに、このリポジトリをアップグレードしてください。 | 選択したバージョン、影響を受けるローカルのフレームワークファイル、実際に必要な資料移行を特定し、既存の研究と有効な Task 条件を維持して、明示的に許可されたアップグレードを実施します。 |
| `.tmp` 内のファイルを調べ、安全に削除できるものを削除してください。 | ファイルの用途と使用状況を確認し、正式な研究資料にまだ保存されていない必要な内容を先に保全します。その後、廃棄可能で、他のアクティブな会話が使っていないと確認できた一時ファイルを削除します。 |
