# Exemples de consignes

[Manuel d’utilisation](<../Manuel d’utilisation.md>)

Décrivez votre objectif dans la langue de votre choix.
Donnez à votre agent des consignes claires dans l’environnement d’exécution d’agents choisi, en vous inspirant des exemples ci-dessous.
Les exemples ci-dessous sont répartis entre les consignes de [configuration](#setup), de [recherche](#research), d’[administration](#administration-instructions), de [rédaction de manuscrits](#writing-instructions) et de [formalisation en Lean](#lean-instructions).
Adaptez les formulations à votre question, à vos fichiers et au périmètre réel de votre travail.

## <a id="setup"></a>Consignes de configuration

Utilisez ces exemples pour préparer votre espace de travail, enregistrer votre identité d’auteur et configurer les ressources locales.
Consultez la section [Configuration](<../Manuel d’utilisation.md#setup>) du manuel pour connaître l’ordre des étapes d’installation et d’enregistrement.

| Exemple de consigne | Actions attendues de l’agent |
| --- | --- |
| <a id="install-acme"></a> Téléchargez et installez ACME (https://github.com/vtejdn/acme) dans `D:\my-math-repository`. | Avant une première installation, confirmer que la racine locale réelle du projet et tout dépôt distant du projet sélectionné ne contiennent aucun contenu ni historique de projet, à l’exception de la configuration initiale de Git. Si une cible est occupée, la préserver, arrêter cette installation et indiquer le côté concerné. Après confirmation que toutes les cibles applicables sont vides, installer les fichiers de la version officielle choisie à la racine du projet sans les métadonnées Git du dépôt officiel ; compléter la configuration nécessaire, vérifier la version et les points d’entrée, puis indiquer l’emplacement, la version et les travaux restants. Une installation ACME existante relève d’une mise à niveau autorisée ; rejoindre une collaboration passe par le clonage de son dépôt de recherche réel. |
| <a id="register"></a> Enregistrez Ali comme ma clé d’auteur ; utilisez Alice comme nom complet. | Après vérification de la clé et des enregistrements existants, utiliser les valeurs fournies : `Ali` comme clé d’auteur et `Alice` comme nom pour l’attribution dans `LICENSE`. Vous enregistrer, ajouter l’attribution en préservant les identités et mentions existantes, et associer cette copie de travail à `Ali` si elle utilise Git. |
| <a id="install-git"></a> Installez [Git](<../git-repository/Dépôts Git.md#notion-git>). | Vérifier si Git est déjà installé, l’installer si nécessaire et indiquer la version disponible ainsi que les éventuelles étapes de configuration restantes. |
| <a id="setup-git"></a> Définissez le nom utilisé pour les commits Git de ce dépôt sur `Alice` et l’adresse électronique sur `alice@email.com`. | Vérifier l’identité Git actuellement utilisée pour les commits de ce dépôt. Configurer si nécessaire le nom et l’adresse électronique fournis au niveau du dépôt ou de l’arbre de travail. Vérifier leur correspondance avec les identités Git enregistrées pour l’auteur et indiquer les valeurs effectives. |
| Expliquez-moi comment me connecter à [GitHub](<../git-repository/Dépôts Git.md#notion-github>). | Expliquer comment se connecter, s’authentifier et relier l’espace de travail à un dépôt distant, en identifiant les étapes que vous devez effectuer vous-même. |
| <a id="test-github-ssh"></a> Testez ma connexion SSH à GitHub. | Tester l’authentification avec `ssh -T git@github.com` en utilisant les paramètres SSH prévus pour Git et, le cas échéant, l’alias d’hôte configuré. Avant d’accepter une nouvelle clé d’hôte, vérifier que son empreinte correspond à une empreinte publiée par GitHub. Considérer le message de confirmation de GitHub comme un succès, même si le code de sortie est `1`. Indiquer le compte mentionné dans le message et tout écart par rapport au compte attendu, ou signaler l’erreur précise. [Guide GitHub pour tester la connexion SSH](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection) |
| J’ai configuré la connexion à GitHub. Testez-la. | Identifier le dépôt GitHub visé et exécuter `git ls-remote` via la connexion SSH ou HTTPS configurée pour ce dépôt afin de vérifier l’accès en lecture. Avec un dépôt vide, la commande peut réussir sans renvoyer de références. Indiquer le dépôt, le protocole utilisé, le compte s’il a pu être vérifié, ainsi que le résultat de la lecture ou l’erreur précise. [Référence Git pour `ls-remote`](https://git-scm.com/docs/git-ls-remote) |
| <a id="setup-repo"></a> Définissez la clé du dépôt sur `〈clé du dépôt〉`. | Vérifier la clé choisie, enregistrer une valeur valide et mettre à jour les références actuelles concernées ; vous demander un autre choix si elle est invalide. La clé du dépôt est indépendante de l’abréviation, du nom complet et du titre du README du projet ; préserver le sens des clés d’auteur, des identités des documents et des informations historiques de provenance. |
| Définissez l’abréviation et le nom complet du dépôt sur `〈abréviation〉` et `〈nom complet〉`. | Enregistrer l’abréviation et le nom complet que vous avez choisis séparément, en vérifiant que chacun est un texte non vide sur une seule ligne. Les utiliser pour former le titre principal du README « 〈abréviation〉: 〈nom complet〉 », maintenir la cohérence entre configuration et titre et préserver le reste du texte. Définir la clé du dépôt séparément de ces choix. |
| <a id="connect-github"></a> Configurez Git et reliez-le à mon dépôt <https://github.com/alice/acme>. | Initialiser Git uniquement si nécessaire, compléter les éventuels enregistrements manquants du nom du dépôt ou de l’auteur selon vos choix, puis associer la copie de travail à votre clé d’auteur. Vérifier ou configurer l’identité des commits pour qu’elle corresponde à votre enregistrement, relier le dépôt distant indiqué et tester l’accès par le compte ou le canal d’authentification pertinent. Préserver les commits existants, les paramètres sans rapport avec la demande et les limites des Tasks, puis indiquer la destination configurée et les étapes de configuration restantes. |
| <a id="clone-repo"></a> [Clonez](<../Manuel d’utilisation.md#notion-clone>) le dépôt de mon collaborateur <https://github.com/alice/acme> et enregistrez-moi sous le nom Bob. | Cloner le dépôt partagé et vérifier la clé d’auteur `Bob`, votre identité réelle et les enregistrements existants. Lors d’un premier enregistrement, demander le nom d’attribution pour `LICENSE` choisi indépendamment avant de vous enregistrer et d’ajouter la mention nécessaire. Réutiliser une identité existante applicable, associer la nouvelle copie de travail Git à la clé vérifiée, préserver les auteurs et documents de recherche existants et expliquer les paramètres d’identité des commits Git. |

## <a id="research"></a>Consignes de recherche

Utilisez ces exemples pour travailler sur la littérature et explorer des questions mathématiques.

### Rechercher, enregistrer ou vérifier la littérature

| Exemple de consigne | Actions attendues de l’agent |
| --- | --- |
| <a id="search-article"></a>Recherchez *On the construction of S* et essayez de l’enregistrer. | Identifier l’œuvre et l’édition, consulter les documents existants et tenter d’obtenir l’original ; compléter la bibliographie et tenir à jour, au besoin, les notes sur l’édition obtenue et l’emplacement de la source. Si l’original contient une table des matières, en préparer une copie interrogeable. Signaler les échecs d’acquisition et les parties indisponibles. |
| Examinez la source locale abc26, enregistrez-la et vérifiez-la. | Identifier l’œuvre, l’édition et l’original local correspondant à abc26, compléter la bibliographie et tenir à jour, au besoin, les notes sur l’édition et l’emplacement de l’original. Si l’original contient une table des matières, en préparer une copie interrogeable. Vérifier le contenu mathématique et consigner le périmètre examiné, les conclusions et les questions non résolues. |
| Vérifiez l’intégralité d’abc26. | Vérifier l’œuvre, l’édition et l’original complet, réutiliser les examens existants et contrôler, section par section, les définitions, énoncés, démonstrations et l’applicabilité des résultats nécessaires. Conserver les contenus utiles et les constats dans les documents appropriés de vérification de la littérature. Indiquer le périmètre réel, les constats, les parties non examinées et les lacunes précises ; préciser si l’original est incomplet ou l’examen inachevé, sans présenter une vérification partielle comme intégrale. Le code Lean associé n’est pas inclus par défaut. |
| <a id="audit"></a>Vérifiez le théorème 1.7 dans abc26. | Repérer le théorème 1.7 dans l’original, vérifier son énoncé complet, ses hypothèses, sa démonstration et l’applicabilité des résultats nécessaires dont il dépend, puis consigner les constats, les parties non vérifiées et les lacunes précises. |
| Comment cette définition est-elle utilisée dans la littérature pertinente ? | Consulter les enregistrements de définitions existants et les sources originales pertinentes, comparer les objets, hypothèses, notations et usages, fournir des références précises et distinguer les définitions des sources des reformulations ou généralisations locales. |

### <a id="start-or-continue-research"></a>[Task](<../Manuel d’utilisation.md#material-task>)

| Exemple de consigne | Actions attendues de l’agent |
| --- | --- |
| <a id="create-task"></a>Créez un Task dans la [ligne W](<../Manuel d’utilisation.md#notion-research-line-letter>) pour la conjecture 1.3 d’abc26. | Vérifier l’énoncé original, les hypothèses et la portée de la conjecture 1.3 et rechercher d’abord un Task existant sur la même question. Si un nouveau Task est nécessaire, utiliser la ligne W et préciser la source, la question exacte et les critères d’achèvement. |
| Créez un Task dans la ligne F : démontrer que P implique Q. | Préciser les objets, hypothèses et quantificateurs de P et Q, créer un Task dans la ligne F avec « P implique Q » comme objectif complet et définir les critères d’achèvement. |
| Créez un nouveau Task pour généraliser la proposition P du cas de dimension finie au cas de dimension infinie. | Vérifier la proposition d’origine, préciser les nouveaux objets, hypothèses et la conclusion visée, créer le Task et conserver la proposition d’origine comme cas particulier que la généralisation doit couvrir. |
| Créez un Task pour trouver, dans le cadre P, une formule générale qui inclut la formule (1) d’abc26. | Vérifier les hypothèses et la notation de la formule d’origine, préciser le cadre P et la portée de la formule générale, puis créer un Task dont les critères d’achèvement comprennent une dérivation correcte et une explication de la manière dont elle couvre la formule d’origine. |
| <a id="start-task"></a>Prenez le rôle d’agent principal de recherche et commencez le Task F0001. | Vérifier l’objectif exact de F0001, l’autorisation, les résultats et stratégies existants, les préférences personnelles d’exécution et l’enregistrement local ; préparer ou réutiliser son enregistrement stable d’exécution selon les besoins. Assumer la responsabilité principale et poursuivre la recherche lorsque les quotas et conditions d’arrêt et de reprise en vigueur le permettent, en conservant résultats utiles, tentatives infructueuses et point de reprise. Activer ou réutiliser la poursuite continue selon les capacités et permissions réelles de l’environnement, coordonner les exécutions existantes du même objectif et éviter de multiplier les agents principaux ou les écritures pour la même exécution. Arrêter la progression concernée et expliquer la limite si une condition d’arrêt non levée s’applique ou si le suivi nécessaire échoue, sans réinitialiser les quotas de sa propre initiative. |
| Commencez le Task F0001 et activez le mode goal. | Vérifier l’objectif de F0001, l’autorisation et les conditions d’exécution en vigueur, puis préparer ou réutiliser l’enregistrement local selon les exigences de démarrage d’un Task. Appeler une fonction goal ou de poursuite continue réellement prise en charge et autorisée par l’environnement, réutiliser une exécution existante du même objectif et conserver les autres objectifs, quotas et conditions d’arrêt et de reprise en vigueur sans inventer de nouveau budget. Après le démarrage, poursuivre la recherche et conserver les résultats et le point de reprise ; arrêter la progression concernée lorsqu’une condition d’arrêt s’applique, sans déclarer achevé un objectif non atteint. Si la fonction est indisponible, expliquer la limite précise et continuer les travaux autorisés réalisables dans l’interaction actuelle, sans prétendre que le mode goal est actif. |
| Commencez à travailler sur le Task F0001 jusqu’à ce qu’il reste 5 % du quota hebdomadaire. | Vérifier l’état actuel du Task et ses conditions d’exécution en vigueur, puis confirmer que la consommation hebdomadaire du compte concerné peut être consultée ; sinon, expliquer la limite et différer la progression. Lorsque les conditions d’exécution sont remplies, avancer et surveiller le quota restant ; s’arrêter dès la première observation d’un quota restant inférieur ou égal à 5 % ou en cas de défaillance du suivi. Conserver les résultats utiles, les questions ouvertes et le point de reprise, puis consigner les conditions d’arrêt en vigueur. |
| Organisez les résultats obtenus jusqu’ici, puis faites une pause. | Terminer la vérification et l’organisation du travail du cycle en cours. Conserver les résultats utiles, les tentatives infructueuses, les questions restantes et un point de reprise utilisable ; consigner la pause ainsi que les conditions toujours en vigueur, puis arrêter toute progression supplémentaire. |
| Faites le point sur l’avancement actuel de F0001. | Vérifier l’état actuel du Task, distinguer les résultats démontrés, les arguments proposés, les observations issues des calculs et les questions ouvertes, fournir les liens vers les documents pertinents et expliquer ce qu’il reste à accomplir pour atteindre l’objectif d’origine. |
| Poursuivez le travail sur le Task F0001. | Lire l’objectif actuel, les stratégies, les résultats existants et les conditions d’arrêt, puis reprendre dans le cadre de l’autorisation actuelle et des limites qui restent en vigueur. Si une condition d’arrêt s’applique toujours, expliquer la raison précise qui empêche la poursuite. |

### <a id="joint-task"></a>[Tasks conjoints](<../Manuel d’utilisation.md#material-task>)

| Exemple de consigne | Actions attendues de l’agent |
| --- | --- |
| <a id="create-joint-task"></a>Créez un Task conjoint dans la ligne F : démontrer que P équivaut à Q. | Préciser les objets, hypothèses et quantificateurs de P et Q, inscrire les deux implications et leurs critères d’achèvement dans le contrat commun, puis rechercher et réutiliser un Task conjoint approprié. N’en créer un sous votre identité d’auteur que si nécessaire. F0001 reste un Task individuel ; préciser son périmètre de participation et ses critères d’achèvement individuels. Conserver les versions antérieures si le contrat doit être révisé, ainsi que les conditions d’exécution et d’arrêt en vigueur ; l’association ne lance ni ne reprend la recherche. |
| <a id="create-personal-task"></a>Examinez le Task conjoint A0001 et créez mon Task individuel. | Repérer et vérifier le contrat commun complet d’A0001, puis rechercher d’abord un Task individuel approprié que vous possédez déjà. Si une création est nécessaire, préciser votre périmètre de participation, vos critères d’achèvement individuels et vos limites supplémentaires, et associer le Task à la version exacte du contrat commun adoptée. Conserver les conditions d’exécution en vigueur ; créer le Task individuel seul ne lance pas la recherche. |
| Orientez mon Task individuel F0001 vers la recherche d’un contre-exemple. | Lire les hypothèses et les quantificateurs de l’énoncé d’origine, préciser les conditions et critères de vérification d’un contre-exemple qui le réfuterait, puis faire de sa recherche et de sa vérification l’orientation individuelle de F0001. Si les critères d’achèvement individuels changent, conserver la version initiale du contrat et consigner la révision. Garder l’objectif commun du Task conjoint et les Tasks des autres participants inchangés, conserver les quotas et conditions d’arrêt, et ne pas lancer ou reprendre l’exécution par ce seul choix d’orientation. |

## <a id="administration-instructions"></a>Consignes d’administration

Utilisez ces exemples pour les opérations [Git](<../git-repository/Dépôts Git.md#notion-git>), les paramètres de l’environnement et la maintenance courante.

### [Commit](<../Manuel d’utilisation.md#notion-commit>) et [push](<../Manuel d’utilisation.md#notion-push>)

| Exemple de consigne | Actions attendues de l’agent |
| --- | --- |
| <a id="commit"></a>Créez un commit de toutes les modifications de l’espace de travail. | Vérifier toutes les modifications de l’espace de travail et leur attribution, créer un commit local du contenu qui doit être suivi par Git, préserver les fichiers exclus par les règles d’ignorance et indiquer le périmètre du commit ainsi que les modifications restantes. |
| <a id="commit-push"></a>Créez un commit et effectuez un push. | Déterminer le périmètre de livraison prévu et préserver les modifications déjà indexées qui n’en font pas partie. Vérifier l’identité des contributeurs, la branche et le dépôt distant cible ; confirmer la connectivité, créer le commit et effectuer le push, puis indiquer le périmètre du commit et le résultat sur le dépôt distant. |
| Créez un commit et effectuez un push des modifications du répertoire du manuscrit de F0001. | Repérer le projet de manuscrit de F0001, ne committer que les modifications du répertoire indiqué qui doivent être suivies par Git et préserver les autres travaux. Confirmer l’identité, la destination et la connexion avant le push et indiquer le périmètre réel. |
| Créez un commit et effectuez un push sans aucune vérification. | Omettre la revue du contenu, les vérifications de format, les tests et les recherches supplémentaires. Effectuer uniquement les vérifications de périmètre, d’identité, de destination et de connectivité nécessaires à la livraison Git, puis créer le commit, effectuer le push et indiquer le résultat. |

| Recevez depuis `〈adresse du dépôt〉` les documents liés au Task A0001 d’Alice. | Vérifier le dépôt source et l’identité d’Alice en tant qu’auteur, sélectionner les résultats, arguments, calculs et vérifications liés à A0001 et nécessaires à cette demande, puis réutiliser les documents existants suffisants ; lors de la réception, conserver l’attribution initiale, les sources exactes, toute la mathématique nécessaire et les limites réelles des vérifications, et signaler les apports nécessaires non obtenus. Mener les recherches ultérieures dans le cadre de votre propre Task et de votre autorisation. |

### Maintenance courante

| Exemple de consigne | Actions attendues de l’agent |
