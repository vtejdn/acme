# 指令示例

[用户手册](../用户手册.md)

用你偏好的语言描述目标。
在你选择的 agent 运行环境中，参考下方示例向 agent 发出清晰的指令。
以下示例分为[设置](#setup)、[研究](#research)、[管理](#管理指令)、[手稿写作](#writing-instructions)和 [Lean 形式化](#lean-instructions)五类指令。
你可以根据实际问题、文件和工作范围调整措辞。

## <a id=setup></a>设置指令

这些示例用于准备工作区、登记作者身份和配置本地资源。
安装与登记的步骤顺序见手册的[设置](../用户手册.md#setup)。

| 指令示例 | Agent 的预期行动 |
| --- | --- |
| <a id="install-acme"></a> 把 ACME (https://github.com/vtejdn/acme) 下载并安装到目录 `D:\my-math-repository` | 首次安装前，确认实际本地项目根目录及任何已选定的项目远端均无项目内容或历史（可保留 Git 初始化与配置）。任一侧已有项目内容或历史时，保留现状、停止本次首次安装，并报告实际占用的一侧。确认适用目标均为空后，将所选官方版本的框架文件安装到项目根目录，不带入官方仓库的 Git 元数据；完成必要设置，核验版本和入口，并报告安装位置、版本及未完成事项。已有 ACME 项目按已获授权的升级流程处理；加入合作则克隆实际研究仓库。 |
| <a id="register"></a> 将 Ali 登记为我的作者键，姓名使用 Alice。 | 核对作者键和已有登记，使用已提供的 `Ali` 作为作者键、`Alice` 作为 `LICENSE` 署名。登记你的身份，添加署名并保留已有身份和声明；若当前工作副本使用 Git，将其关联到 `Ali`。 |
| <a id="install-git"></a> 安装 [Git](../git-repository/Git仓库.md#notion-git) | 确认是否已安装 Git；需要时安装，并报告可用版本和必要的后续设置。 |
| <a id="setup-git"></a> 将本仓库的 Git 提交姓名设置为 `Alice`，邮箱设置为 `alice@email.com`。 | 核对本仓库当前生效的 Git 提交身份。需要时在仓库或工作树范围配置所提供的姓名和邮箱。核验这些值与已登记作者的 Git 身份映射一致，并报告实际生效的值。 |
| 告诉我如何连接 [GitHub](../git-repository/Git仓库.md#notion-github) | 说明登录、认证和连接远程仓库的步骤，并指出需要你完成的操作。 |
| <a id="test-github-ssh"></a> 测试我的 GitHub SSH 连接。 | 使用 Git 将采用的 SSH 设置运行 `ssh -T git@github.com`。如配置了 SSH 主机别名，改用该别名。接受新的主机密钥前，核对其指纹是否与 GitHub 公布的指纹一致。收到 GitHub 的认证成功提示时，即使退出码为 `1` 也表示认证通过。报告提示中的账号及其与预期账号的差异，失败时报告具体错误。 [GitHub SSH 连接测试指南](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection) |
| 我已配置好 GitHub 连接。请测试连接。 | 确定目标 GitHub 仓库，使用为该仓库配置的 SSH 或 HTTPS 连接执行 `git ls-remote`，检查读取权限。空仓库可以成功响应并返回空的引用列表。报告目标仓库、所用协议、已核实的账号（如有），以及读取结果或具体错误。 [Git 的 `ls-remote` 参考文档](https://git-scm.com/docs/git-ls-remote) |
| <a id="setup-repo"></a> 设置仓库键为`仓库键` | 验证所选仓库键，记录有效值并更新受影响的当前引用；无效时请你另选。仓库键独立于项目缩写、全名和 README 标题，作者键、材料身份和历史来源事实按原有含义保留。 |
| 设置仓库缩写和全名为`仓库缩写`，`仓库全名` | 记录你分别选择的项目缩写与全名，确认均为非空单行文本；用两项形成 README 主标题“〈缩写〉: 〈全名〉”，使配置与标题一致并保留其余正文。仓库键与这两项分别设置。 |
| <a id="connect-github"></a> 设置 Git，连接到我的仓库 <https://github.com/alice/acme>。 | 仅在需要时初始化 Git，按你的选择补齐缺失的仓库名称或作者登记，并将工作副本关联到你的作者键。核对或配置提交身份，使其与登记对应，连接指定远端，并通过相关账号或认证通道测试访问。保留已有提交、不相关设置和 Task 限制，报告已配置的目标及剩余设置事项。 |
| <a id="clone-repo"></a> [克隆](../用户手册.md#notion-clone)我的合作者仓库 <https://github.com/alice/acme>，并将我登记为 Bob | 克隆共享仓库，核对作者键 `Bob`、你的实际身份和已有登记；首次登记时先补问独立选择的 `LICENSE` 署名姓名，再登记并添加必要署名。复用适用的已有身份，将新 Git 工作副本关联到经核对的作者键，保留已有作者和研究材料，并说明 Git 提交身份的设置情况。 |

这些示例用于处理文献和进行数学探索。

### 查找、登记或审计文献

| 指令示例 | Agent 的预期行动 |
| --- | --- |
| <a id="search-article"></a>搜索 On the construction of S，尝试入库 | 识别作品与版次，检索已有材料并尝试获取原文；补齐书目，按需维护取得版次及来源位置的说明。原文有目录时，整理为可检索的文献目录。报告获取失败、不可用部分。 |
| 查看本地文献 abc26，入库并审计 | 核对 abc26 的作品、版次和本地原件，补齐书目，按需维护版次及原文位置说明。原文有目录时，整理为可检索的文献目录。审计其数学内容，记录实际检查范围、结论和未解决问题。 |
| 全文审计abc26 | 核对作品、版次和完整原文，复用已有审查，逐节核查定义、陈述、证明及必要依赖的适用性，将有用内容和审计发现保存在适当的文献审查材料中。报告实际覆盖范围、发现、未检部分和具体缺口；原文不完整或检查未完成时明确说明，不将局部检查称为全文审计。配套 Lean 代码不默认纳入。 |
| <a id="audit"></a>审计文献 abc26 的定理 1.7 | 定位原文定理 1.7，核查完整陈述、假设、证明及必要依赖的适用性，记录审计结论、未检部分和具体缺口。 |
| 这个定义在相关文献如何使用的？ | 查阅已有定义记录和相关原文，比较对象、假设、符号及使用场景，给出准确引用，并区分来源定义与本地改写或推广。 |

### <a id="start-or-continue-research"></a>[研究任务](../用户手册.md#material-task)

| 指令示例 | Agent 的预期行动 |
| --- | --- |
| <a id="create-task"></a>把 abc26 中的猜想 1.3 设为 [W 系](../用户手册.md#notion-research-line-letter)任务 | 核对猜想 1.3 的原文、假设和范围，先查找已有同题 Task；需要新建时使用 W 系，写明来源、精确问题和完成标准。 |
| 建立 F 系任务：证明 P 蕴含 Q | 明确 P、Q 的对象、假设和量词，以“P 蕴含 Q”为完整目标建立 F 系 Task，并明确完成标准。 |
| 将命题 P 从有限维情形推广到无限维情形，建立新任务 | 核对原命题，明确新对象、假设和拟证明的结论，建立 Task，并将原命题保留为应涵盖的特例。 |
| 设置任务：找到在 P 情形下的一般公式，能覆盖 abc26 中公式 (1) | 核对原公式的假设和记号，明确 P 情形及一般公式的适用范围；建立 Task，把公式的正确推导及其如何涵盖原公式写入完成标准。 |
| <a id="start-task"></a>你是主研究 agent，开始推进任务 F0001 | 核对 F0001 的确切目标、授权、已有成果和策略、个人执行偏好及本地执行记录，按需准备或复用该任务的稳定执行记录。承担主研究职责，在有效额度、停止及恢复条件允许时持续推进研究，保留有用结果、失败尝试和续研位置；按运行环境的实际能力与权限启用或复用持续执行功能，协调同目标的已有运行，避免重复主研究和写入。遇到尚未解除的停止条件或必要监测失效时停止相关推进并说明限制，不自行重置额度。 |
| 开始任务 F0001，拉起 goal 模式 | 核对 F0001 的目标、授权和有效执行条件，按开始任务的要求准备或复用本地执行记录。调用运行环境实际支持且获准使用的 goal 或等效持续执行功能，复用同目标的已有运行，保留其他目标和仍有效的额度、停止及恢复条件，不自行增加预算。启动后持续推进研究并保留结果及续研位置；触发停止条件时停止相关推进，未达目标不宣称完成。功能不可用时说明具体限制，并在现有交互中继续可开展的授权工作，不声称已开启 goal。 |
| 开始推进任务 F0001，直到周用量剩余 5% | 核对任务现状和有效执行条件，确认能读取适用账户的周用量；无法读取时说明限制并暂缓推进。满足执行条件后推进研究，监测剩余额度，在首次观测到剩余不高于 5% 或监测失效时停止，保留有用结果、未决问题和续研位置，并记录有效停止条件。 |
| 整理当前进展后暂停 | 完成当前轮次的核查与整理，保留有用结果、失败尝试、剩余问题和可继续的位置，记录暂停及仍有效的条件，然后停止继续推进。 |
| 汇报 F0001 的当前进展 | 核对任务现状，区分已证明结果、候选论证、计算观察和未决问题，给出相关材料链接，并说明距离原始目标还缺什么。 |
| 继续推进任务 F0001 | 读取当前目标、策略、已有成果和停止条件，在本次授权及仍有效的限制内恢复推进；遇到尚未解除的停止条件时，说明阻碍继续的具体原因。 |

| <a id="commit-push"></a>提交，推送 | 确定本次交付范围，保留其他暂存工作，核对真实身份、分支和目标远端；确认连接后创建提交并推送，报告提交范围和远端结果。 |
