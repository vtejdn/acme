## ACME：自律的・協働的な数学探究

ACME は、自律的・協働的な数学研究のための軽量なフレームワークです。
[AI エージェント](#notion-agent)向けの Markdown ルールと補助スクリプトを組み合わせ、継続的な探究を支え、確認・再利用・継続が可能な形で研究成果を保存します。
主な目的は、人間の数学者の指導のもとで自律的な AI エージェントが数学研究を進めることと、人間の著者どうしの協働を支えることの二つです。

### 人間の数学者

人間の数学者は、次の役割を担います。

1. 研究上の問い、許可する範囲、完了基準を定め、[研究課題（Task）](#material-task)を開始する。
2. [エージェント](#notion-agent)とともに[研究戦略（Strategy）](#material-strategy)の展開を導く。
3. アイデアを提供し、数学的な意図を明確にし、研究上の優先順位を定め、議論を問い直し、問いを洗練し、研究の方向を調整する。
4. 研究成果を理解し、数学的知識の最前線を探る。
5. 数学的な結果に責任を持つ。

### [大規模言語モデル（LLM）](#notion-llm)によって動作するエージェント

許可された範囲内で、自律的な[エージェント](#notion-agent)は次の役割を担います。

1. 文献を読み、研究に必要な結果を検証する。
2. [研究戦略（Strategy）](#material-strategy)を発展させて評価し、欠落を見つけ、与えられた作業の範囲内で通常の方法上の判断を自律的に行う。
3. 開かれた問いを探究し、新たな結果の適用範囲と限界を明確にする。
4. 具体的な問いについて証明や反例を探し、再現可能な計算を行って、観察、根拠、着想を得る。
5. [Claim](#material-claim) や [Ledger](#material-ledger) を含む適切な研究資料に、仮定、議論、根拠、依存関係、有益な失敗したアプローチ、未解決の問い、研究上の実質的な経緯を保存する。
6. 必要に応じて独立した[検証（Review）](#material-review)を手配し、その範囲、所見、限界を記録する。
7. 数学執筆の一般的な基準と担当著者の方針に従って、原稿を作成・検証する。

### 協働

数学者は、共有 [Git リポジトリ](git-repository.md#notion-git-repository)を通じて協働し、研究資料を共有して互いの成果を再利用できます。
リポジトリは [GitHub](git-repository.md#notion-github) などのプラットフォームでホストでき、共同研究者はそれぞれの端末で作業し、変更を同期できます。
[Git リポジトリを使った協働の模式図](git-repo.png)を参照してください。

同じリポジトリの共同研究者は、共通の数学的目標について共同 [Task](#material-task) を設け、共通の問題、仮定、完了基準を明確にできます。
各参加者は自分の Task で参加範囲を明確にし、[研究戦略（Strategy）](#material-strategy)を通じて具体的な研究の進め方を整理します。
数学的作業の重複を減らし、AI 用の計算資源をより効率的に利用するため、共同研究者と相談して異なる研究戦略を選ぶことを勧めます。
独立した検証、再現または相互確認のために、意図的に同じ研究方針を採用することもできます。

異なる数学者やチームも、[受け入れ（Intake）](#notion-intake)を通じて選んだ資料を取り込み、リポジトリをまたいで協働できます（[リポジトリ間の協働の模式図](collaboration.jpg)を参照）。

### 作業の流れ

研究は、人間が完了基準を明確にして定めた [Task](#material-task) から始まります。
[エージェント](#notion-agent)は、まず関連するローカルの研究資料と文献を確認・再利用し、必要に応じてインターネットで追加の情報源を探します。
結果の適用可能性を確認し、[研究戦略（Strategy）](#material-strategy)を発展させ、証明、計算、反例探索を繰り返します。
各試行は次の試行の手がかりになります。
有益な所見、失敗、未解決の問いは、[Claim](#material-claim) や [Ledger](#material-ledger) を含む適切な研究資料に保存されます。
戦略は、許可された目標の範囲内で調整されます。
候補となる結果は数学的な[検証（Review）](#material-review)を受け、Task の完了は当初の基準に照らして判断されます。

[作業の流れの図](workflow.jpg)を参照してください。

## <a id="setup"></a>セットアップ

新しい研究プロジェクトでは、以下の手順 I–III を順に進めてください。
既存の共同研究に参加する場合は、まず作業環境を整え、その後、共同研究への参加手順に従ってください。

### 手順 I：適切な能力を持つ[大規模言語モデル](#notion-llm)を選ぶ

研究水準の数学的な問題に対する大規模言語モデルの性能を比較してください。
[FrontierMath Tier 4](https://epoch.ai/frontiermath/tiers-1-4?tier=Tier+4+%28v2%29&view=graph&tab=leaderboard)、[MathArena](https://matharena.ai/models)、[Riemann-bench](https://surgehq.ai/benchmarks/riemann-bench) などの関連する評価を参考にできます。
数学研究や管理作業に使うモデルを選ぶ際は、オープンソースかどうか、利用のしやすさ、費用を考慮してください。

### 手順 II：作業環境を整える

一台の端末で個人研究を行う場合は、適切な[エージェント実行環境](agent-harness.md)を選び、十分な能力を持つ[大規模言語モデル](#notion-llm)に接続してください。

1. エージェント実行環境をインストールします。
   独立したアプリケーションでも、[統合開発環境（IDE）](agent-harness.md#notion-ide)内で使うものでも構いません。
   必要に応じて、または希望する場合にログインしてください。
2. フレームワークと今後の研究資料を保存するフォルダーを端末上で選びます。
3. 設定画面またはモデル選択画面で、モデルとサービス提供者を選びます。

[Git](git-repository.md#notion-git) を使わない場合、既定の利用形態は自分の端末上での個人研究です。
複数の端末間で作業を同期したり、共有 [Git リポジトリ](git-repository.md#notion-git-repository)を通じて協働したりする場合は、[GitHub](git-repository.md#notion-github) などのホスティングプラットフォームを選べます。
研究記録をアップロードすることと、リポジトリを公開することは、それぞれ別の選択です。

4. （任意）端末に Git をインストールするか、選んだ実行環境の[エージェント](#notion-agent)にインストールを依頼します。
5. （任意）リポジトリホスティングサービスのアカウントを作成するかログインし、既存のリポジトリに接続するか、新しいリポジトリを作成します。

- [セットアップの指示例](user-instructions/指示例.md#setup)を参照してください。

### 手順 III：フレームワークをインストールして初期設定する

参加する既存の研究リポジトリに ACME がすでに含まれている場合は、次の節の手順に従ってください。

1. [エージェント](#notion-agent)に [ACME フレームワーク](https://github.com/vtejdn/acme)をプロジェクトフォルダーへダウンロードするよう依頼します。
   [Git](git-repository.md#notion-git) を使う場合は、そのリポジトリを[クローン](#notion-clone)することもできます。
2. `Alice` や `Ali` などの一意な著者キーを選び、それとは独立に `LICENSE` の著者表示に使う名前を選びます。
   エージェントに著者登録とその著者表示の追加を依頼します。
   Git の作業環境では、この作業コピーを自分の著者キーに関連付け、新しい記録に正しい著者情報が使われるようにすることも依頼してください。
3. （Git を使う場合）[コミット](#notion-commit)に使う氏名とメールアドレスを設定するか、エージェントに設定を依頼します。
4. （Git を使う場合）研究[リポジトリ](git-repository.md#notion-git-repository)の短い名前を選択または確認し、フレームワークに正しく記録されていることをエージェントに確認してもらいます。
5. （任意）適切な時点で、公開リポジトリを通じて研究記録を共有することを強く勧めます。

- [セットアップの指示例](user-instructions/指示例.md#setup)を参照してください。

### 協働者として既存の [Git リポジトリ](git-repository.md#notion-git-repository)に参加する

1. リポジトリのホスティングプラットフォームにログインし、共同研究者からの招待を承認します。
2. 共有リポジトリへのアクセス設定を[エージェント](#notion-agent)に依頼します。
3. リポジトリのアドレスをエージェントに渡し、新しいローカルフォルダーへ[クローン](#notion-clone)するよう依頼します。
   そのフォルダーをエージェント実行環境で開きます。
4. 研究リポジトリにまだ登録されていない場合は、協働者とは異なる著者キーを選び、それとは独立に `LICENSE` の著者表示に使う名前を選んでから、
   エージェントに登録とその著者表示の追加を依頼します。
   ACME でこの作業コピーを自分の著者キーに関連付けることも依頼してください。
5. [Git](git-repository.md#notion-git) の[コミット](#notion-commit)に使う氏名とメールアドレスを設定するか、エージェントに設定を依頼します。

- [セットアップの指示例](user-instructions/指示例.md#setup)を参照してください。

## 使い始める

### Task を始める

1. （任意）関連文献を提供するか、[エージェント](#notion-agent)に検索を依頼します。
   資料の原本ファイルを[ローカル文献フォルダー](../mathematics/literature/pdf)に保存し、関連記事の指定した部分を、求める深さで検証するようエージェントに依頼してください。
2. エージェントと話し合って [Task](#material-task) を設定し、問い、制約、完了基準を明確にします。
   Task と関連資料を整理するために、[研究ラインの文字](#notion-research-line-letter)を選ぶことができます。
3. 継続的な自律研究では、実行上の制限と停止条件を指定するか、既存のものを採用します。
4. 必要なツール操作の承認を求められたら対応し、エージェントからの質問に答えます。
5. エージェントが作成した数学資料の内容を自分で考え、理解してください。
   この作業を代わりに行えるエージェントはいません。
   エージェントと数学について議論し、理解を深め、理解が進むのを助けてもらってください。
   関連する参考文献を求め、議論やアイデアの出所をソクラテス式の問いかけで確かめてください。
   特に、明示的な出典なしにモデルの知識へ依存している議論では重要です。
6. （任意、[Git](git-repository.md#notion-git) を使う場合）保存したい変更を[コミット](#notion-commit)します。
   必要に応じてローカルの編集を取り消したり、既存のコミットをリバートしたりできます。
   他の数学者と協働する場合は、[プッシュ](#notion-push)、[プル](#notion-pull)、[マージ](#notion-merge)、競合の解消をエージェントに依頼してください。

- [研究の指示例](user-instructions/指示例.md#research-instructions)を参照してください。

### 注意事項

- [エージェント](#notion-agent)は、公開されている文献を[ローカル文献フォルダー](../mathematics/literature/pdf)へダウンロードしようとします。
  既定では、[Git](git-repository.md#notion-git) はこのフォルダーを無視します。
  自分の非公開資料をここに置く場合は、Git がこのフォルダーを無視し、公開リポジトリへアップロードしないことを確認してください。
- 協働者どうしで著者キーが重なる場合は、`Wang1`、`Wang2` のように異なるキーを決めてください。
- 異なる主研究エージェントが並行して進める [Task](#material-task) には、異なる[研究ラインの文字](#notion-research-line-letter)を使ってください。
  Task の設定時に文字を選び、資料の番号付けを分け、書き込みの競合を減らします。
  索引、文献一覧、リポジトリの識別情報など、共有ファイルの変更はエージェント間で調整するよう依頼してください。
  並行研究用の worktree を別途作ることは勧めません。
  フレームワークには、その管理手順が定められていません。
- ACME は、文書化されたルールと補助ツールによってエージェントを導きます。
  エージェントがあなたの指示やフレームワークのルールから外れた場合は、違いを説明し、影響を受けた作業を修正するよう依頼してください。
- フレームワークのルールには、曖昧さ、不整合、欠落がある場合があります。
  必要だと考える場合は、エージェントにルールの修正を依頼できます。
  ACME フレームワークの[著者](https://github.com/vtejdn)へ知らせることもできます。

### 役立つ習慣

- フレームワークについて疑問があれば、いつでも[エージェント](#notion-agent)に尋ねてください。
- 文献をクラウドサービスで同期されるローカルフォルダーに保存している場合は、ディレクトリジャンクション（directory junction）を使って[ローカル文献フォルダー](../mathematics/literature/pdf)をその保存先につなぐよう、エージェントに依頼してください。
  そのフォルダー内のファイルを読み取り、管理するために必要な権限をエージェントに与えてください。
- エージェントが認証情報を使う作業を自動化する場合は、機密情報を適切に保管し、[Git](git-repository.md#notion-git) の管理対象から除外してください。

## 実用情報

### フレームワークのバージョン

現在のフレームワークのバージョンは 0.5.0 です。

自動確認が有効で、ネットワークへのアクセスが許可されている場合、
[エージェント](#notion-agent)は作業開始時に、UTC の各日につき最大一回、[公式 ACME フレームワーク](https://github.com/vtejdn/acme)の新しいバージョンを確認します。
新版がある場合は、インストール済みのバージョンと利用可能なバージョンを示して、アップグレードを手配するか確認します。
判断を待つ間も現在の作業を続けられます。
通知だけではファイルのインストールや更新は行われず、アップグレードを後回しにできます。
このリポジトリの自動確認の無効化や有効化、今すぐの再確認、または明示的なアップグレードを指示できます。

### ルート直下のディレクトリとファイル

以下の表は、リポジトリのルートにある主なファイルとディレクトリを説明しています。
必要になったときにのみ作成されるディレクトリもあります。

| パス | 役割 |
| --- | --- |
| `.tmp/` | [エージェント](#notion-agent)が作成し、使用後に削除する一時的な入力や副生成物を保存します。 |
| `execution/` | 個人の研究 [Task](#material-task) の現在の実行状態、制限、停止条件を記録します。 |
| [`framework/`](../framework/readme.md) | フレームワークのルール、資料テンプレート、書式仕様、バージョンの案内を保存します。 |
| `intake/` | 他の[リポジトリ](git-repository.md#notion-git-repository)から受け入れた資料、その出典、各取得の範囲を記録します。 |
| [`mathematics/`](../mathematics/readme.md) | 研究資料、文献記録、計算、原稿、発表資料を保存します。 |
| `profiles/` | 個人の研究方針、実行上の設定、数学執筆の方針を保存します。 |
| [`repository/`](../repository/readme.md) | リポジトリの設定、著者登録、外部リポジトリと著者の対応関係を保存します。 |
| [`scripts/`](../scripts/readme.md) | セットアップ、資料管理、案内、確認に使う任意のコマンドラインツールを提供します。 |
| [`user-manual/`](./) | 利用ガイド、セットアップの説明、指示例を保存します。 |
| `.gitattributes` | 改行コードを含め、テキストファイルとバイナリファイルの [Git](git-repository.md#notion-git) による扱いを設定します。 |
| `.gitignore` | Git が無視する未追跡のファイルとディレクトリを指定します。 |
| `AGENTS.md` | 適用されるフレームワークのルールと資料へエージェントを導く入口の指示を提供します。 |
| `LICENSE` | リポジトリのライセンス条項と通知を記載します。 |
| `readme.md` | リポジトリを紹介し、ユーザーマニュアル、フレームワークのルール、研究資料へのリンクを示します。 |

使用するツールや設定によっては、以下のディレクトリも存在します。

| パス | 役割 |
| --- | --- |
| `.agents/` | リポジトリ内のエージェント用スキルを保存します。 |
| `.claude/` | このワークスペースのローカルな Claude Code 設定を保存します。 |
| `.codex/` | このワークスペースのローカルな Codex 設定を保存します。 |
| `.git/` | Git の履歴、参照、設定、その他のバージョン管理情報を保存します。 |
| `.venv/` | ローカルの Python 仮想環境と、インストール済みの依存パッケージを保存します。 |
| `.vscode/` | VS Code のワークスペース設定と推奨拡張機能を保存します。 |

| J | 計算（Computation） | [`mathematics/computations/programs/`](../mathematics/computations/readme.md) | 再現可能な計算のプログラムと必要な入力を整理し、実行状態、結果、限界を記録します。 |
| U | 文献検証単位（Literature audit unit） | [`mathematics/audits/literature/`](../mathematics/audits/literature/readme.md) | 出典の版と該当箇所、数学的な内容、適用可能性、確認の限界を記録し、検証済みの文献を再利用できるようにします。 |
| — | 原稿（Manuscript） | [`mathematics/manuscripts/`](../mathematics/manuscripts/index.md) | 論文や関連する数学文書を、その説明、引用、執筆方針、コンパイル記録とともに作成します。 |
| — | 発表資料（Presentation） | [`mathematics/presentations/`](../mathematics/presentations/readme.md) | 想定する聴衆に向けた講演やスライドを、ソースファイル、執筆方針、コンパイル情報、検証記録とともに準備します。 |

- 各計算には、プログラム、必要な入力、`readme.md` を含む、番号付きの J ディレクトリがあります。
  生成された出力は、ローカルで [Git](git-repository.md#notion-git) の管理対象外となる `mathematics/computations/outputs/<J>/` に別途保存されます。
- 文献検証単位は、`mathematics/audits/literature/` 内で引用キーごとにまとめられます。
- [定義索引](../mathematics/definitions/index.md)は、定義、用語、記号を概念ごとに整理し、完全な記述を保存する担当の C、L、U 資料へリンクします。
- 正本となる[文献一覧](../mathematics/literature/references.bib)には、出版物の識別情報と引用キーを記録します。
  出典の取得状況、ファイルの版、利用可能性は、別途[文献登録簿](../mathematics/literature/registry.md)に記録します。

### 基本概念

| 用語 | 意味 |
| --- | --- |
| <a id="notion-llm"></a>LLM（大規模言語モデル） | 大量のテキストで訓練され、数学的な説明やコンピューターコードを含む言語を処理・生成できる AI モデルです。 |
| <a id="notion-agent"></a>エージェント（Agent） | [LLM](#notion-llm) によって動作し、タスクの計画と実行、ツールの使用、結果に応じた行動の調整ができる AI システムです。[エージェント実行環境](agent-harness.md)を通じて、人間の利用者が許可した範囲と制限の中で動作します。まだ [Agent](https://ja.wikipedia.org/wiki/%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88_%28%E3%83%9E%E3%83%88%E3%83%AA%E3%83%83%E3%82%AF%E3%82%B9%29) に進化したわけではありません。 |
| <a id="notion-context"></a>コンテキスト（Context） | モデルを一度呼び出す際に LLM が利用できる情報で、指示、会話履歴、提供された資料、ツールの結果を含みます。現在のコンテキストには、[セッション](#notion-session)の履歴全体のうち、選択した部分や要約だけが含まれる場合があります。 |
| <a id="notion-context-length"></a>コンテキスト長（Context length） | LLM が一度に処理できる入力と出力の合計の最大長で、通常は token（テキストの小さな単位）で測ります。指示、会話履歴、提供された資料、生成される応答を含みます。 |
| <a id="notion-session"></a>セッション（Session） | [エージェント実行環境](agent-harness.md)によって管理される、[エージェント](#notion-agent)との継続的なやり取りです。複数の会話ターンを含むことがあり、各ターンは通常、利用者のメッセージで始まり、エージェントの応答とツール操作を含みます。実行環境は会話履歴を保持し、モデルを呼び出すたびに[コンテキスト](#notion-context)を準備します。モデルの[コンテキスト長](#notion-context-length)に収まるよう、以前の履歴を選択したり要約したりする場合があります。 |
| 資料識別子 | 資料と、該当する場合はその版を指定する構造化された識別子です。例えば、`Alice_C_F0007_v1.md` は、著者、種類、研究ライン、通し番号、版によって [Claim](#material-claim) を識別します。 |
| <a id="notion-research-line-letter"></a>研究ラインの文字 | 番号付きの研究資料を整理するための文字で、例えば `Alice_C_F0007_v1.md` の `F` です。Task から派生した資料は Task の文字を引き継ぎますが、それぞれ別の通し番号を持ちます。研究ラインを指定しない場合の既定値は `A` です。 |
| 著者キー | `Alice` など、登録済みの人間の著者に対する安定したキーです。資料識別子や著者記録で使われます。 |
| 資料ファミリー | `Alice_C_F0007_v1.md` と `Alice_C_F0007_v2.md` のように、同じ資料について保存されている各版です。 |
| 資料の版 | Claim の `v1` や `v2` のように、保存された資料の特定の改訂版です。 |
| <a id="notion-main-research-agent"></a>主研究エージェント | [Task](#material-task) の研究を主導し、参加する他のサブエージェントを調整し、研究記録の整合性を保つエージェントです。 |
| Task の作業ラウンド | 一つの Task に取り組む作業期間です。終了時に、進捗、未解決の問題、続きに取りかかれる箇所を記録します。 |
| <a id="notion-git-branch"></a>Git ブランチ（Branch） | [Git リポジトリ](git-repository.md#notion-git-repository)内の名前付きの開発ラインで、他の作業ラインと分けて変更を進められます。 |
| <a id="notion-clone"></a>クローン（Clone） | 既存の Git リポジトリを、ファイルとバージョン履歴を含めて新しいローカルフォルダーへコピーすることです。 |
| <a id="notion-commit"></a>コミット（Commit） | ローカルの [Git](git-repository.md#notion-git) 履歴に保存された一つの状態で、選択した変更と、その説明を記録します。 |
| <a id="notion-push"></a>プッシュ（Push） | ローカルのコミットをリモート Git リポジトリに送り、記録済みの作業をリモートで利用できるようにすることです。 |
| <a id="notion-pull"></a>プル（Pull） | リモート Git リポジトリから変更を取得し、ローカルの作業へ取り込むことです。 |
| <a id="notion-merge"></a>マージ（Merge） | 別の[ブランチ](#notion-git-branch)の変更を現在の Git ブランチに統合し、必要に応じて編集の競合を解消することです。 |
| <a id="notion-intake"></a>受け入れ（Intake） | 別の公開 ACME リポジトリから選択した研究資料を自分のリポジトリへ取り込み、著者の帰属、由来、検証の限界を保つことです。 |
| 引用キー | 文献一覧の各文献を識別する短い識別子で、研究記録や原稿内で一貫して引用するために使います。 |

### <a id="material-task"></a>研究課題（Task）

Task は、明確に定めた数学的目標、許可された範囲、合意された完了基準を中心に研究を整理します。

| Task の状態 | 読者にとっての意味 |
| --- | --- |
| `proposed` | 研究の問いが提案されていますが、まだ現在取り組む研究目標にはなっていません。 |
| `active` | 研究が許可され、継続中です。 |
| `paused` | 研究を意図的に一時停止しており、再開する意向と明示された再開の根拠があります。 |
| `blocked` | 入力の不足や満たされていない前提によって、次に必要な手順へ進めません。進捗を再開するために必要な条件が記録されています。 |
| `completed` | 合意された完了基準が満たされ、対応する数学的根拠と必要な検証によって支えられています。 |
| `retired` | 研究は打ち切られています。理由、有益な所見、未完了の部分は引き続き記録されています。 |

- 現在[エージェント](#notion-agent)が作業していなくても、Task は active のままであることがあります。
- Task は、その研究を支える資料をまとめます。
  関連する原稿、進捗報告、その他の依頼した文書は、`mathematics/manuscripts/Alice_T_A0007/` のようなプロジェクトに集めることができます。
- 関連する目標の研究を続けるために、完了した Task の再有効化を依頼できます。
  次に何を研究したいか、範囲や制限にどのような変更があるかを説明してください。
  実質的に異なる研究目標には、新しい Task を設定します。

### <a id="material-strategy"></a>研究戦略（Strategy）

Strategy は、研究目標へ向かう具体的な方針を、その仕組み、残る障害、次の有益な作業とともに示します。

| Strategy の状態 | 読者にとっての意味 |
| --- | --- |
| `proposed` | 考えられる方法を見いだしていますが、まだ現在の研究方針として選択されていません。 |
| `active` | Task の目標を進めるための方針として、現在選択されています。 |
| `paused` | 優先順位、作業の順序、利用可能な資源を理由に、一時的に保留しています。数学的な失敗を意味しません。 |
| `blocked` | 特定の前提が満たされておらず、次に予定する手順へ進めません。障害と、方針を再開するための条件が記録されています。 |
| `completed` | その方針が掲げた結果や貢献が得られ、必要な根拠によって支えられています。Task の完了には、なお別の作業が必要な場合があります。 |
| `refuted` | 記載された仮定のもとで、確認済みの数学的根拠が、記録された仕組みを排除するか、その仕組みに必要な補助的主張を否定しています。 |
| `superseded` | 明示された後継の Strategy に置き換えられたか、別の方針に組み込まれています。経緯と有益な所見は引き続き参照できます。 |

- 一つの [Task](#material-task) に複数の Strategy があり、代替案になる場合も、組み合わせた方法の各部分になる場合もあります。
  一つの Strategy を完了、一時停止、除外しても、それだけで Task 全体の状態が決まるわけではありません。
- 方法を提案したり、代替案の比較を[エージェント](#notion-agent)に依頼したり、優先順位を指定したりできます。
  優先順位や順序を固定する必要がある場合は、明示してください。
  それ以外の場合、エージェントは合意された範囲内で方針の選択を調整できます。
- 許可された範囲内で、自律的なエージェントは、所見や資源の変化に応じて、Strategy の追加、改訂、優先順位の変更、分割、統合、一時停止、再開を行えます。
- 失敗した方針からも、有益な情報が得られることがあります。
  障害を明らかにしたり、ある方法を排除したり、追加の仮定が必要な箇所を示したりできます。

### <a id="material-claim"></a>数学的命題（Claim）

Claim は、重要で厳密に定式化された数学的主張と、その妥当性について現在分かっていることを記録します。

| 数学的な状態 | 読者にとっての意味 |
| --- | --- |
| `open` | 記載どおりの主張は未解決です。部分的な結果、帰着、候補となる議論があっても、`proved` または `refuted` とする条件はまだ満たされていません。 |
| `proved` | 完全な証明によって、記載された仮定のもとで記載どおりの主張が確立されています。必要な根拠となる結果はすべて確立され、適用可能であり、記録された数学的な[検証](#material-review)では残る欠落が見つかっていません。 |
| `refuted` | 確認済みの反例または議論によって、記載された範囲内で記載どおりの主張が否定されています。必要な根拠となる結果はすべて確立され、適用可能であり、記録された数学的な検証では残る欠落が見つかっていません。 |

### <a id="material-review"></a>検証記録（Review）

Review は、[エージェント](#notion-agent)による数学的主張や議論の確認を、正確な入力と範囲、所見、未解決の限界とともに記録します。

| 検証者と作業の関係 | 読者にとっての意味 |
| --- | --- |
| `self-reviewed` | 証明の形成に参加したか、その過程の数学的な議論を知っているエージェントが、証明を確認しています。 |
| `independently reviewed` | 別のエージェントが証明を確認しており、その形成に参加せず、関連する議論も自分の[コンテキスト](#notion-context)として引き継いでいません。 |
| `unknown` | 過去の検証や出典由来の検証について、実際の関係がまだ確定できていません。誤りがあることも、独立した確認が行われたことも意味しません。 |

- これらのラベルは、検証を行うエージェントと証明との関係を示し、証明が正しいかどうかを示すものではありません。
  関係の宣言がないことは `unknown` とは異なります。
  検証を選択していない場合、その Claim が検証の根拠を採用していないことだけを意味します。
- 別のエージェントでも、証明形成時の議論、数学的な要約、著者の説明、過去の検証結果を引き継いでいれば、その確認は自己検証に当たります。
  [セッション](#notion-session)やモデルを変えるだけでは、独立性は確立されません。
- [主研究エージェント](#notion-main-research-agent)は、証明の重要な箇所で独立した検証を手配し、[Task](#material-task) 完了後には論理の連鎖全体に対する独立した検証を手配します。
  特定の結果や証明の一段階の検証を依頼することもできます。

### <a id="material-ledger"></a>探究記録（Ledger）

Ledger は、比較、失敗したアプローチ、方向転換の理由など、有益な数学的探究を保存します。
一つの記録には、何を研究したか、どの仮定を使ったか、何を試したか、推論や根拠が何を示したか、何が未解決かを記載できます。

研究がまだ独立した [Claim](#material-claim) になっていない場合でも、Ledger に部分的な議論や有益な着想を残せます。
例えば、失敗した試行や結論の出なかった試行は、障害を明らかにし、方法の違いを示し、同じ作業の繰り返しを避けるのに役立ちます。

- [Strategy](#material-strategy) の比較、失敗した試行の説明、複数の出典からの所見の統合、後の作業に役立つ推論の保存を、[エージェント](#notion-agent)に依頼できます。
- 数学的に実質があり、記録する価値があると考える内容は、何でもエージェントに記録を依頼できます。
