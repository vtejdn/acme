# ACME 使用手册

[用户请求示例](user-instructions/用户指令.md) · [关于](../about.md)

## 人类与 AI 协作开展数学研究

ACME，即 Autonomous and Collaborative Mathematical Exploration，支持人类研究者与自主 AI agent 协作，探索数学前沿并发展新的数学结果。
它保留论证、证据和未解决问题，使研究能够被检查、复用和继续推进。

你确定研究目标和授权范围，澄清数学意图，并把握研究重点。
在整个过程中，你都可以贡献想法、质疑论证、细化问题和调整研究方向，包括决定进一步发展哪些结果以及如何呈现它们。

在这一范围内，agent 研读并核查文献、发展策略、构造证明与反例、开展可复现的计算，并撰写手稿。
它们也审查论证、识别缺口，保留假设、依赖关系、有价值的失败尝试和未解决问题。
指派范围内的常规方法选择可由 agent 自主作出。

研究过程将问题的提出、文献核查、策略发展、证明与计算、审查和手稿撰写联系起来，各环节之间可以相互反馈。
相互关联的数学陈述及其支持证据，使工作能够在不同 agent 和会话之间延续。
框架区分猜想、计算观察、证明草稿和经过审查的结果，使每项结论的依据与局限保持清晰。
参见[关于](../about.md)和 [AI 使用披露](../ai-disclosure-for-human-authors.md)。

本手册介绍环境、安装及日常使用。
[用户请求示例](user-instructions/用户指令.md)帮助你说明有用工作，并理解可以期待的结果。
[导出清单](../framework/export-manifest.json)标明当前安装的框架版本。

## 推荐工作环境

使用能够按你的实际授权读写仓库文件、运行终端并检查 Git 状态的 agent 环境。
支持 UTF-8 和 Markdown 的文本编辑器便于检查陈述、链接及决定。
按[协作规则](../framework/rules/identity.md#collaboration-maintenance-and-conflicts)，直接在共享研究仓库及已有工作区中工作。
不建议额外并行研究副本，框架也不为其规定管理流程。

使用随附命令接口和纯净导出需要 Git 及 Python 3.12 或更新版本。
通用运行时使用 Python 标准库；独立 Python 环境是便利配置，不是额外框架服务。
示例从仓库根目录使用实际可用的解释器运行。
具体计算可能需要其复算说明列出的库。
编译 TeX 手稿时需要 LaTeX，实际包含 Lean 代码或形式化的工作才需要 Lean。
获取来源需要访问所选资源；私密设置按[本地私密配置规则](../framework/rules/organization.md#machine-local-locators)留在负责人的忽略配置中。
框架不要求特定操作系统、agent 产品、机器路径或托管服务。

## 安装与首次设置

<a id="选择起点"></a>
### 加入已有合作

使用已有仓库，阅读[数学入口](../mathematics/readme.md)、相关 Task 和实际材料。
需要时登记实际人类，并在写入前明确绑定当前实际操作者；不要重新初始化已有内容的研究仓库。
共享人类登记库记录身份，工作区绑定为其中的会话提供当前操作者归属。
绑定不改变材料的负责作者、另一作者的政策或实际 Git 签名。
交付时使用真实登记的 Git 姓名／邮箱映射，参见[身份规则](../framework/rules/identity.md#stable-keys-and-local-attribution)。

### 建立独立空白仓库

从框架来源使用受支持的[纯净导出接口](../framework/exporting.md)：

```powershell
python scripts/export-framework.py ../new-research --repository Demo --dry-run
python scripts/export-framework.py ../new-research --repository Demo
```

将目标路径和仓库键替换为实际选择。
父目录必须已存在，目标须为新路径或合格空目标。
纯净导出创建全新身份及空研究结构，并保留合格目标已有的 Git 元信息。
它不覆盖已有内容的仓库，也不复制研究、个人政策、来源签名或执行授权。
它不获取远端内容、不提交，也不推送。

省略 `--author` 时，人类登记库为空，工作区未绑定。
先登记实际人类，再明确绑定：

```powershell
python scripts/research.py identity-add Alice --display-name "Alice Example"
python scripts/research.py identity-bind Alice
```

将示例身份替换为负责人的实际声明键。
导出时明确使用 `--author Alice`，则直接登记并绑定所选的这一人类，但不继承来源签名或政策。
写入材料或提交前配置实际身份映射和本地选择。
准确接口及副作用见[脚本文档](../scripts/readme.md)。

普通研究使用已安装规则。
研究请求、执行纠正、检查失败和个人偏好本身不授权框架改动、获取或版本变更。
另行授权的框架维护保留其实际指定范围。

## 日常使用

### 向 agent 布置研究任务

说明数学问题、定义域、假设和量词、期望成果及授权探索范围。
说明较弱结果是否有用，以及能否解决原问题。
持续自主工作时，明确或采用执行限制和停止条件。
[请求示例](user-instructions/用户指令.md#开始或继续研究)可帮助措辞，无须指定内部材料操作或工具序列。

实际的实质目标使用精确 Task 契约；讨论、文献阅读或维护本身不启动数学 Task。
提出 Task、数学 Task 处于活跃状态和 agent 此刻正在运行，是不同事实。
用量停止不解决数学问题，新会话或 Task 修订也不重置额度或恢复已停止的运行。
每个本地 Task 家族都有一个当前执行边界，建立时为非运行，完成后仍保留。
其中只保留适用的准确 Task 决定与仍有效条件，不保存用量日记或会话历史。
应能从更新中了解已确立事实、不确定性、有用失败及下一步有区分力的行动。
参见 [Task](../framework/rules/tasks.md)和[执行规则](../framework/rules/execution.md)。

### 沿数学材料阅读

从 Task 的选定决定和精确契约出发，阅读实际支持、路线和审查发现。
对于 Claim，检查选定陈述、论证、依赖及适用审查，不凭编号相同推定关系。

| 材料 | 应在其中阅读什么 |
| --- | --- |
| T — Task | 精确问题、授权、完成标准和生命周期决定 |
| C — Claim | 精确可复用陈述、评估及选定论证／证据 |
| S — Strategy | 路线、处置、优先级、Task 关联和下一步 |
| D — Draft | 发展中的数学和未解决替代方案 |
| L — Ledger material | 探索、综合分析、有意义的失败及适用的范围内自审或关系未知的结论 |
| R — Review | 实际检查的数学输入、发现、审查关系及限制 |
| J — Computation | 原生程序、必要数据、复算背景及真实运行状态 |
| U — Source unit | 准确来源版次／段落、适用性及实际检查深度 |

定义、书目和手稿项目各有负责位置。
不必为每个草算创建 Claim 或独立审查记录。
这些材料使实际论证、来源及审查范围可以检查；索引帮助定位，不决定状态。

### 理解状态与审查证据

| 数学状态 | 对读者的含义 |
| --- | --- |
| `open` | 精确但未解决的陈述，可以没有论证。 |
| `proof draft` | 论证正在发展、存在缺口或等待所需审查。 |
| `conditional` | 结论依赖明确未解决的输入或额外条件。 |
| `proved` | 完整论证覆盖陈述，依赖已解决，且实际完成内部审查。 |
| `refuted` | 已检查证据在所述范围内否定该准确陈述。 |

审查状态另记为 unreviewed、under review、self-reviewed、independently reviewed 或 changes required。
完整且自审的证明可以登记为 `proved` 支持推进；独立审查要求另行组织的审查者实际检查相关推理。
关键证明点及 Task 完成后的完整逻辑链需要独立审查安排，未完成义务须保留。
阅读审查覆盖的输入、版本、论证及排除范围。
旧版或较窄范围的审查不会自动覆盖改变后的证明或契约。
形式化验证、发表和人类审查另有各自事实，参见 [Claim 评估](../framework/rules/claims.md)和[审查规则](../framework/rules/proof-audits.md)。

### 修订与继续研究

描述预期变化，指出实际结果或文档。
说明问题、假设或结论是否应改变，还是只希望在数学不变时澄清措辞。
应得到对结果影响的说明、有用既有发现的保留，以及剩余局限。
除非你明确固定优先级或顺序，策略可随发现和资源调整；路线变化不扩大目标。

继续工作时说明 Task 或实际文档，以及变化后的范围或限制。
轮次收尾应提供保留结果、剩余义务和可用下一步。
本轮结束不等于满足 Task 原始标准，执行暂停也不等于数学完成。
参见[继续与收尾请求](user-instructions/用户指令.md#结束轮次或停止工作)。

### 合作与跨仓库接收

本地协作者使用已登记的可读姓名；外部来源使用本仓库的仓库、作者编号并明确来源对应。
同名或同地址本身不证明身份，继续转发时按接收仓库自己的编号解释。
Agent 准备所选本地家族位置与原始来源事实，实际无法解决的身份冲突才需要你裁定。

已登记合作者直接在共享仓库工作，保留实际人类归属，各负责作者的实质工作在各自材料中按授权开展。
按[协作边界](../framework/rules/identity.md#collaboration-maintenance-and-conflicts)，agent 可直接修复另一作者材料中的日常行政位置，包括同对象链接和导航。
保留实际数学、输入、来源身份及审查含义；日常维护不转移作者归属，也不接管另一人类的 Task/E。

行政冲突按适用框架规则处理；规则不明确时，报告具体竞争内容并提请人类裁决。
实质数学冲突须先获人类批准，再按已说明范围进行数学复核；同范围已有明确批准时直接沿用。
批准复核本身不授权实质编辑另一作者的材料。
普通已授权研究和日常维护不增加一律审批的要求。

从独立研究仓库复用时，保留实际原始归属及审查限制；同仓库的其他作者属于直接协作。
说明需要复用的发现及预期用途。
应得到清楚的取得范围、不可用输入及未检查内容说明。
复制文档不认可其中全部发现，也不授予其研究授权。

### 文献计算与手稿

说明所需作品、版次、段落及检查深度。
书目识别出版物，来源记录说明实际检查内容，结果应明确适用性及局限。
取得文件、可用性、来源检查及来源证明审查是不同结果。
成功复制或摘要匹配不确立作品身份、完整性或定理。
有目录的来源可先用[可检索目录](../mathematics/literature/contents/readme.md)定位章节，再阅读实际原文。
目录命中用于定位，未命中不证明结果不存在。
来源为文集中的部分、部分扫描或原始 HTML 时，应询问实际覆盖范围及可读性。
除非明确要求，来源审计不包含相关 Lean 代码。

本地 PDF、原始 HTML 及资源文件不进入 Git/GitHub，也不通过跨仓库接收复制。
复用来源单元保留其原有阅读范围，不表示本地已持有原文；需要原文时另行按普通授权取得来源。

计算时给出问题、输入、参数及需检查范围。
应得到算术方式、实际结果及局限，包括失败。
有限扫描和浮点观察不证明不受限的定理；精确检查也需要明确范围及数学归约。

写作时指明手稿、负责作者、读者、数学范围和来源或风格选择。
已有作者及手稿选择继续适用，切换当前操作者不改变它们。
说明新偏好仅适用于本稿，还是更广的作者范围。
报告或演示文稿保留你明确指定的文档目录，并遵守同样的来源、构建及审查职责，不因目录位置另建研究 Task。
直接复用文字时，可在全作者写作选择中指定自己的独著／合著作品，或为具体手稿指定来源及例外。
仅作风格参考不授予文字复用许可，仍须保留归属并适合当前数学。
参见[文字复用规则](../framework/rules/writing.md#default-reuse-permission)。

应得到实际引用支持，以及数学审查、编译和已完成版式检查的明确说明。
编译成功不证明数学，文本修改本身也不完成研究目标。
[写作请求](user-instructions/用户指令.md#撰写或修订手稿)说明如何指定范围。

### 日常命令与发布

用[请求示例](user-instructions/用户指令.md)描述普通工作，需要准确可选命令时阅读[脚本文档](../scripts/readme.md)。
说明待交付文件或提交，必要时指定目标，以及应先满足的条件。
提交按真实状态保存选定工作，包括未完成工作；推送交付获授权的提交，并应报告实际远端结果。
检查或审查在请求范围回答问题，单纯 Git 交付不是数学审查。
普通提交／推送不重新开展研究审查、运行框架回归或盘点来源库。
参见[交付请求](user-instructions/用户指令.md#提交与推送)。

## 常见问题

**每个猜想都需要证明吗？**
Open Claim 可以只有未解决问题的陈述，没有论证。

**每个中间 Claim 都需要我批准吗？**
指派范围内的普通探索与结果整理可以推进，变更目标和实际授权边界仍适用。

**能直接修改索引状态吗？**
实际状态来自负责数学材料及其证据，仅修改索引不改变该评估。

**Agent 停止是否意味着 Task 阻断或完成？**
执行状态与数学生命周期分开，应保留未解决问题和交接。

**提问前需要读完全部规则吗？**
从目标和本手册开始，agent 阅读适用行动及主题规则。
