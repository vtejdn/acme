# Reuse of Mathematical Knowledge

<a id="reuse-before-proof"></a>

## Reuse Existing Knowledge Before Proving

Apply the [work-obligation triggers](workflow.md#work-obligations) to the next action.
Substantial proof investment means committing to develop a nontrivial argument or resolve a substantive proof gap, including an intermediate step; it is not measured by a fixed number of lines or minutes.
A brief direct calculation to learn what to conjecture need not await a search, while a sustained proof attempt remains subject to this check even within an exploratory route.
Recognition of a known result has its own [source-check trigger](#recognized-known-results).
For a Git working repository with a configured remote, complete or reuse the [common work-start update](workflow.md#shared-repository-work-starts) before substantive work and use relevant incoming changes in local mathematical reuse, independently of whether an external literature search is needed.

Prefer using established definitions, results and proof mechanisms to reconstructing them as project contributions.
Use [common source preparation](literature.md#source-preparation) during research, audit and writing, including the existing duties for complete definitions.
For personal import or external intake, apply the [original-preparation rule](literature.md#acquisition-before-u-reception).
Before investing substantial work in a nontrivial intermediate claim, definition-related assertion, or main argument, state the exact needed conclusion and hypotheses, then search in this order:

1. Check existing Claims, arguments, relevant source audits, related strategies, constructions, useful failures and prior search findings by the needed conclusion and problem features.
   Verify their actual conditions, scope and review limits.
2. If those inputs are insufficient, look for applicable local sources under [common source preparation](literature.md#source-preparation) and use [progressive reading](literature.md#progressive-reading) for the actual question and edition.
3. If local mathematics and literature are insufficient, use the [public repository index](../../intake/reuse-repositories.md) to find related ACME results, proof mechanisms, source inspections, counterexamples, programs or inputs under the [relevant directory-refresh rule](literature-search.md#public-repository-discovery-and-reuse).
   Read the actual candidate materials and necessary context before judging applicability; an index summary or repository description supplies no accepted mathematical input.
4. When those layers remain insufficient, search other external literature and primary sources for results, alternative formulations, proof techniques and counterexamples under the [search policy](literature-search.md#autonomous-literature-search).

Stop advancing through these layers once there is sufficient usable evidence.
This priority requires neither visiting every repository nor delaying an already identified adequate primary source, and grants public ACME work no higher mathematical authority.
When an existing result covers the needed step, check its assumptions and invoke it directly, citing the project Claim and supporting proof version or the external source as appropriate.
Reconstruct its underlying lemmas only when the available conclusion is insufficient, a concrete objection needs investigation, or the task requires that reconstruction.
Reuse an adequate previous search within its recorded scope; ordinary substitutions, definition expansions and direct calculations need no separate search for every line.
This check precedes substantial proof attempts and is not reserved for stalled routes.
If a bounded search remains unproductive, retain its scope and unresolved question and proceed to a justified derivation or other method under the existing stopping rules.
Failure to find a result does not establish novelty.

A related route can guide an attempt without supplying a proved input.
Check the actual fixed mathematical sources before invoking a theorem and explain the consuming route's local objects, parameters, missing hypotheses and remaining gap.
Ordinary source attribution and meaningful failure retention continue; no method-use registry or reciprocal feedback step is required.

| Available input | Use in the project |
| --- | --- |
| An established external result, including known equivalence or well-definedness of definitions | Check and cite it; record an external proof dependency when invoking it, or source attribution when giving a self-contained proof. Do not create a project Claim merely to reprove it. |
| A notation conversion, parameter substitution or direct specialization | State the conversion and verify applicability in the source audit or consuming argument; no automatic new Claim |
| A result that covers only part of the needed conclusion or requires a substantive extension | Reuse the established part and isolate the remaining project argument or gap; register substantive reusable deductions under the claim rules |
| A related mechanism, analogy or possible counterexample | Inspect its scope and explain how it informs the strategy; a lead does not itself discharge a proof obligation |

Before relying on an external theorem, apply the [external-input acceptance and proof-review rules](literature-audits.md#accepted-external-inputs) at the depth its actual use requires.
If a previously registered project claim is later covered by a source, update its provenance and supporting inputs with the appropriate review and history; retain its ID and earlier artifacts rather than maintaining a redundant obligation to prove it independently.

Record searches that materially affect an argument or strategy under the [search evidence rules](literature-search.md#search-evidence).
New deductions and changed dependencies follow the [mathematical-operation rules](ledger.md#substantive-mathematical-operations); routine searches need no separate log.

### When a Known Result Is Recognized

Recognizing a substantive step as a named or established theorem triggers a source check during exploration, even when its proof is short, the agent can reproduce it, or an existing local proof has passed review.
A plausible identification is a search lead until checked.
Reuse an adequate recorded source check first, then search local literature and external sources as needed.
A local proof alone can settle the mathematics without settling the source attribution; it is not sufficient evidence to stop the latter check.
Complete the source check or handle its unresolved facts and follow-up under the [pending-literature rule](records.md#pending-literature-work) before handing off the research step; do not defer it silently to manuscript preparation.

Check a precise source statement and locator, match the hypotheses and conclusion, and record whether the source is an actual proof input, attribution for a known result proved locally, or a related result that does not cover the step.
Follow the [dependency distinctions](claims.md#dependencies-and-corrections).
Source attribution remains necessary when retaining a self-contained proof, including when such a proof is explicitly requested.
A suitable checked reference is sufficient; identifying the earliest publication is required only for a priority claim.
Reuse existing bibliography, useful source-edition notes and adequate audit records without a new Claim, index or mandatory standalone file.

If the source cannot yet be verified, retain the actual search scope, unresolved identification and use limits in the responsible source record or consuming argument, with still-needed follow-up in maintenance under that rule and the existing stopping conditions.
Do not assert a verified attribution or treat the source as an accepted input.
Assess any independently supported local proof separately under the [external-input rules](literature-audits.md#accepted-external-inputs).
Ordinary direct calculations still need no source search for every line.
