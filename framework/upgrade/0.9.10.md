# Upgrade from 0.9.9 to 0.9.10

The preceding official tag `0.9.9` identifies [commit 7f7c47d81497c79f7687bde3d01a60d0342f9476](https://github.com/vtejdn/acme/commit/7f7c47d81497c79f7687bde3d01a60d0342f9476).
The target is `0.9.10`.
This PATCH release applies to existing `0.9.9` installations.

## Changes

- Generalize the default Git delivery permission in `framework/rules/identity.md` to every authorized repository writing task with an applicable project remote.
  Ordinary commit and push of that task's deliverable no longer depend on a joint Task, multiple authors or a separate push instruction.
  The agent judges a useful coherent scope and timing and actively completes delivery within actual limits.
  Share useful progress when appropriate and assess remaining delivery at task or round closeout, without committing every edit or waiting for an entire Task or proof to finish.
- Align `AGENTS.md`, `framework/agent-actions.md`, `framework/rules/workflow.md`, `framework/rules/tasks.md` and `framework/rules/execution.md` with the common [Git delivery rule](../rules/identity.md#submission-checks).
  Keep collaborative progress guidance, local E, effective stopping conditions and mathematical decisions at their existing responsible homes.
  Delivery supplies no authority to resume research, reset limits, adopt mathematics or change another author's content.
- Align authorized installed-upgrade delivery in `framework/versioning.md` with the same default for single-author and collaborative repositories.
  An applicable project remote also permits ordinary scoped delivery for authorized framework development, maintenance and target-copy work under their existing activity responsibilities.
  The official framework repository's existing version and stable-tag requirements continue to govern its actual publication.
- Align personal import and export preparation in `framework/rules/intake.md` with the same default for the authorized transfer's actual repository writing scope.
  Use the actual receiving or export project destination and honor explicit human limits, including commit-only work.
  Public releases beyond ordinary scoped Git delivery, research resumption and whole-library migration or deduplication require their applicable authority.

Explicit local-only, commit-only, offline, postponed-synchronization and publication-scope limits remain effective under the common rule.
Apply the revised default to current authorized work after installation, subject to still-effective human restrictions.
Keep the actual project destination, authorized outgoing scope, contributor identities, host permissions and existing integration and connection-recovery boundaries.
A configured source remote or successful connection alone creates no writing assignment or publication target.
No separate delivery approval, authorization register, mandatory tool sequence, scheduled push or historical compatibility mechanism is added.
