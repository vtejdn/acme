# Upgrade from 0.5.0 to 0.6.0

The preceding source is `0.5.0` at [official commit a3a8ef2e3c2d5f4318e7d5402e9634ca5ba68c7d](https://github.com/vtejdn/acme/commit/a3a8ef2e3c2d5f4318e7d5402e9634ca5ba68c7d); the target is `0.6.0`.
Removing initialization URL arguments is incompatible during 0.x development.
Use the [installed-framework upgrade procedure](../versioning.md#upgrading-an-installed-framework).

## What changed

- **Configuration and setup.** `repository/config.json` and the initialization helpers retire `repository_url` and `layout_format`, add `repository_display_name` and `repository_abbr`, and stop generating local-human `registered_by`.
  `scripts/acme/core/repository.py`, `identity.py`, the identity/action rules and `repository/readme.md` use native Git project targets and independent project, human and License names.
- **Navigation and publication.** Blank Claim/Task indexes lose retired Role and Historical-only assessment columns.
  `scripts/acme/materials/render.py` reuses the shared publisher in `scripts/acme/core/publication.py`, including interrupted-write recovery; current output and count interfaces remain.
  Workflow, Claim, strategy and record guidance allow bounded direct navigation edits or optional rendering.
- **Tools and receiving.** The ledger, literature, versioning, intake, record and action rules, material format and `scripts/readme.md` clarify optional helpers and agent-led adaptation under the receiver's current rules, without a sender-version gate or new receiving format.
- **Human documents.** The six manuals under `user-manual/` in English, Chinese, French, German, Japanese and Spanish update their version sentence to `0.6.0` and retain supplied separately maintained prose changes.
  Supplied changes also include `user-manual/user-instructions/用户指令.md`.

No earlier shipped path is removed or moved.

   These fields do not configure Git; retain actual native remotes and do not create a replacement URL mirror or initialize Git.
2. Remove retired `init --url` from affected local invocations.
   Remove the old `url` argument from local calls to `Repository.initialize` and `identity.initialize`, passing remaining optional Python arguments by keyword so a former positional URL cannot become a Git identity.
   Check those callers against the new signature; `research.py source-add --url` and `material.py fetch-source --url` retain their source-specific roles.
3. Add the two display settings using already established human choices, or null for missing choices, while preserving the chosen repository key.
   When both are known, maintain the root heading as `# <repository_abbr>: <repository_display_name>` and preserve the remaining README.
   Otherwise retain the existing heading and report the missing choices; an existing project does not adopt the official starting repository's display values.
4. Remove `registered_by` from local-human entries in `repository/people.json`, retaining other registration facts, actual author/source attribution and checkout binding.
   Do not re-register people or reconstruct registrar history; verify those entries and the actual binding remain coherent.
5. Adapt existing populated Claim/Task navigation from its real materials rather than copying blank indexes.
   Remove the retired main-table Role cells/column, retaining nine columns, and Historical-only assessments from Fixed History, retaining Family, Material version and Decisions.
   Preserve selected statuses, review findings and joint participation; Role in an Unacquired Source Inputs table remains an input relation.
