# Upgrade from 0.9.2 to 0.9.3

The predecessor is official tag `0.9.2` at [246413a57ba2026ca11e904480930e6dcf501be3](https://github.com/vtejdn/acme/commit/246413a57ba2026ca11e904480930e6dcf501be3); the target is `0.9.3`.
This PATCH release clarifies installation targets and source retrieval without changing material schemas or command-line interfaces.
Use the [installed-framework upgrade procedure](../versioning.md#upgrading-an-installed-framework).

## What changed

- **Installation target.** Root `readme.md`, `framework/agent-actions.md`, `framework/readme.md`, `framework/versioning.md` and `scripts/readme.md` install selected official files into the actual project root, keeping source retrieval separate from the final target.
  Ordinary installation no longer recommends adopting an official clone and its history as the research project; actual collaboration clones, framework development and explicit clone instructions retain their scope.
  Existing project content and Git metadata/history remain, and temporary source belongs in a creator-owned child of root `.tmp/` when needed.
- **Human documents.** The six manuals under `user-manual/` in English, Chinese, French, German, Japanese and Spanish carry setup-body updates and the `0.9.3` version sentence.
  Supplied installation examples change in `user-manual/user-instructions/user-instructions.md`, `用户指令.md`, `Exemples de consignes.md`, `Anweisungsbeispiele.md`, `指示例.md` and `Ejemplos de instrucciones.md` within that same instruction directory.
  Synchronize these target files while preserving actual local instructions and adaptations.

Only this upgrade note is added; no earlier public path is removed or moved, and no installer, command or configuration field is added.

## Additional actions for this version

Ordinary synchronization suffices for an existing installation, preserving its actual project root, content, identity and Git relationships.
No retrospective workspace scan, reinstallation or automatic relocation/deletion of nested repositories is required.
An actually misplaced copy is handled only under its concrete assignment and existing content/Git/cleanup protections.

No mathematical-material migration, renumbering or bulk repository relocation follows from this upgrade.
