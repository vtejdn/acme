# Upgrade to 0.12.0

ACME `0.12.0` follows `0.11.1` at the [official release commit](https://github.com/vtejdn/acme/commit/71ff388d6b9a9c3d14ad00747bb5902cfe3a26a0).
This note covers existing installations upgrading from that release.

## Changes

- **Personal notes.** `framework/agent-actions.md`, `framework/rules/preferences.md` and `framework/rules/writing.md` specify when to read relevant notes and terminology for ordinary repository conversation, direct manuscript edits and summaries of writing conventions or experience.
  Before delivery, record lasting author choices in their applicable preference or manuscript home and reusable agent experience in the existing advisory notes.
  Apply a one-off correction within the requested work. [Personal guidance](../rules/preferences.md#personal-communication-and-writing-guidance)
- **Disposable computation outputs.** `mathematics/computations/outputs/` can be cleared in full on an authorized request once applicable local adaptation is complete and the directory is idle.
  At adoption, retain necessary fixed data or sufficient reconstruction and verification materials in their responsible home.
  The [computation rules](../rules/computations.md#computation-output-location), action guide, `framework/rules/organization.md`, `framework/rules/identity.md`, `framework/templates/mathematics/computation.md` and `mathematics/computations/readme.md` use the same boundary.
- **Checks scoped to actual use.** `framework/material-format.md` and `scripts/readme.md` describe the updated checks for viewing, verifying, writing and acquiring material.
  Display and navigation check the selected review finding's relationships and binding declarations without reading native computation payloads.
  Explicit verification and material writes check the fixed inputs required by the actual operation, including the inputs bound by an adopted review finding.
  `material.py create --task`, personal import with `reuse`, and decision appends or reselections use the relevant Task context, reused material or selected decision without reopening unrelated historical inputs.
  The implementation changes `documents.py`, `importing.py`, `indexes.py`, `runtime.py`, `tasks.py`, `validation.py` and `write.py` in `scripts/acme/materials/`, and `scripts/acme/intake/acquire.py`. [Material checks](../material-format.md#explicit-checks-during-construction)
- **Manuscript literature search.** `framework/agent-actions.md`, `framework/rules/writing.md` and `mathematics/manuscripts/readme.md` route an explicit manuscript search request to a statement-by-statement comparison in the manuscript's `literature-seek.md`.
  `citation.md` continues to map external sources actually cited in TeX.
  Substantive new mathematical findings follow the existing evidence and review rules before the affected manuscript text is revised. [Search action](../agent-actions.md#search-literature-for-manuscript-statements)
- **User documentation.** The main manuals, instruction examples in `user-manual/user-instructions/` and Git guides in `user-manual/git-repository/` have updated text in English, Chinese, French, German, Japanese and Spanish.
  The manuals and examples cover manuscript literature search and the follow-up for new mathematical findings, and give Windows junction examples using `mathematics/literature/pdf/` relative to the current repository.
  The instruction examples also cover direct clearing of local computation outputs and the default Git delivery scope.
  The Git guides and setup examples explain when GitHub project setup includes the `acme-math` Topic and what a request limited to local remote configuration does. [User manual](../../user-manual/user-manual.md)

## Additional actions for this version

Ordinary synchronization and bounded merges of local edits suffice for a working copy with no affected computation output dependency. [Installed-framework upgrade procedure](../versioning.md#upgrading-an-installed-framework)

When an explicit upgrade or ordinary Git integration introduces the clearing rule, check that working copy for legacy output files that serve a current consumer, hold necessary continuation state or constitute known fixed evidence.
Retain the required data or checkpoint in the responsible J's fixed `inputs/` home, or establish sufficient reconstruction where the actual dependency permits it.
Repair the exact references and preserve the object and scope of any review that used it.
Verify that the repaired references and retained prerequisites suffice with empty outputs. [Local adaptation](../rules/computations.md#adapting-outputs-in-an-existing-working-copy)

Finish the applicable adaptation before advancing `framework/version.json` during an explicit upgrade.
If Git has already brought in the new rules and version metadata, complete any outstanding adaptation in that working copy before its first affected clear.
If a needed file is missing, use the existing [recovery procedure](../rules/computations.md#recovery-of-necessary-fixed-inputs), report any unresolved dependency and leave the affected directory intact until the adaptation is complete.
Preserve the current Task/E stops and allowances throughout.
Clear outputs only on a separate authorized request. [Direct clearing](../rules/computations.md#clearing-local-computation-outputs)
