## Existing-project action

Existing manuscript and presentation projects must be moved and adapted to the new writing organization during this upgrade.
An old project location is not retained as a compatibility or author-designated exception merely because it already exists.

1. Before retiring an existing home, read its actual writing assignment, responsible record and necessary content to establish writer(s), purpose and corresponding Task.
   Use a joint container only for actual explicitly requested joint writing, not merely because a Task is joint or a publication lists several authors.
   Clarify only a decisive missing fact rather than infer responsibility from an old directory name, the Task creator or a byline.
2. Move Task-associated projects to the actual writer or joint-writer container followed by the complete Task family.
   Genuine writing without a corresponding Task moves to its writer container and a purpose-named home without manufacturing T/E.
   Preserve all necessary document sources, choices, citation maps, actual reviews, unresolved revisions, build inputs and needed local files, including untracked content and its existing output exclusions.
3. Repair affected indexes, incoming and outgoing references, build instructions, included-file paths, source maps and local ignore exceptions, then check the actual moved documents and direct consumers.
   Resolve occupied destinations without overwriting an unrelated project, duplicating the manuscript or returning to the retired layout.
4. Remove the retired homes after necessary content and consumers are handled, keeping no alias, redirect, symlink, shadow copy or compatibility reader.
   Finish all required project moves and adaptations before advancing `framework/version.json` or reporting completion; do not defer them until the next writing request.

Installations without existing writing projects need ordinary rule synchronization and bounded local merges, with no invented project or migration record.
