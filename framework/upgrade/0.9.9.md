# Upgrade from 0.9.8 to 0.9.9

The target is `0.9.9`.
The preceding official tag `0.9.8` identifies [commit 1792696ed2f09f2751a7ba7bf537c626a020233a](https://github.com/vtejdn/acme/commit/1792696ed2f09f2751a7ba7bf537c626a020233a).
This PATCH release applies to existing `0.9.8` installations.

## Changes

- Define [Task number reuse](../rules/tasks.md#task-number-reuse) in `framework/rules/tasks.md`.
  After an authorized deletion or move to another research line, a locally authored Task number can be reused in its original author and line sequence once the applicable release conditions below are met.
  Maintain affected references and carry any existing E to the new address on a line move, preserving its state and effective conditions.
  The new Task starts at `v1` with its own contract and decision.
  Any later E preparation follows the existing execution rule.
- Align `framework/rules/identity.md`, `framework/rules/records.md`, `framework/material-format.md` and the general identity guidance in `framework/rules/workflow.md` with this Task rule.
  Ordinary allocation continues to use the existing monotone `material_next` bound, and the agent explicitly selects a confirmed released number for reuse.
- Clarify the supported working-copy boundary in `framework/rules/identity.md` and the existing handoff in `framework/rules/execution.md`.
  The framework supports one working copy per author for a given repository.
  Parallel or alternating use of multiple copies by one author falls outside the supported scope.
  An actual replacement uses the [same-human handoff](../rules/execution.md#responsibility-and-version-boundary) to preserve known effective conditions in the continuing copy.
  E stays local to its working copy, and automatic matching or synchronization across copies falls outside the supported scope.
  Task maintenance checks affected inputs and references within the supported working copy under the existing write and integration rules.

### Literature preparation

- Clarify [common source preparation](../rules/literature.md#source-preparation) in `framework/rules/literature.md` and route the [general action entrance](../agent-actions.md#scope-and-instruction-handling) in `framework/agent-actions.md` to that rule.
  Register confirmed works of reference value in the existing bibliography during any authorized repository action or related discussion, including when no original is needed.
  For a necessary original, reuse adequate evidence, look for applicable local copies before public acquisition, and prefer a complete suitable edition with the newer verified edition favored under equal conditions.
  Preserve the exact edition locators still used by existing evidence.
  Tell the human author when a necessary original cannot be obtained from permitted public sources, keep its confirmed bibliography entry, and use the [existing maintenance worklist](../rules/records.md#pending-literature-work) for the concrete outstanding action.

### Manuscript bylines

- Set the [byline default](../rules/writing.md#document-choices-and-final-review) in `framework/rules/writing.md` and apply it in the [ordinary writing checks](../rules/writing.md#manuscript-writing-rule-checks) when the title or byline is in scope.
  Omit the byline from new manuscripts and leave a format-required author field empty by default.
  Use a byline specified by the responsible human in the current instruction or through an applicable writing choice.
  Routine revision preserves an established byline, and project ownership and source attribution stay in their existing records.

### Task, manuscript and literature safeguards

- Refine the release rule in `framework/rules/tasks.md`.
  Keep a number unavailable while a maintained branch retains the former Task or needs its address.
  A joint Task already published as a source eligible for external intake, or with an established external receiving correspondence, keeps its original family address reserved even after retirement or deletion.
  Apply the existing outgoing review in `framework/rules/identity.md` to affected joint Task source addresses, including ancestors first exposed by the same push.
  Hold affected delivery that would expose conflicting original identities, even when the tip has removed the conflict.
- Clarify in `framework/rules/execution.md` how the agent confirms the intended Task and effective local conditions before execution after a branch change.
  Document the structural scope of the optional current-E check in `scripts/readme.md`, leaving actual continuity to the agent.
  A genuine authorized replacement can read an explicitly selected old E for a one-time handoff, with any existing receiving E protected.
- Clarify the writing-home rule in `framework/rules/writing.md` and its entrance in `mathematics/manuscripts/readme.md`.
  Preserve an occupied manuscript project and its entrances, and choose a distinct home for an unrelated Task that reuses its number.
  A line move of the same Task preserves the actual manuscript association and updates affected entrances, keeping the project location when suitable.
- Bound bibliography writes in `scripts/acme/intake/bibliography.py`, `scripts/acme/intake/literature.py` and `scripts/acme/intake/acquire.py`.
  Selected updates preserve unrelated entries and effective BibTeX directives, and an unchanged bibliography keeps its original bytes.
  If a bounded edit cannot preserve existing content, the helper refuses before writing any selected files.
  The retrieval helper in `scripts/acme/intake/literature.py` accepts files below root `.tmp/` or the logical `mathematics/literature/pdf/` store and rejects other targets before retrieval.
  Align these optional interfaces in `scripts/readme.md`.

### Prepared work and selected file access

- Consolidate preparation-input responsibility in `framework/rules/workflow.md` under [prepared work and input applicability](../rules/workflow.md#prepared-work-and-input-applicability).
  Align `framework/rules/tasks.md`, `framework/rules/strategies.md`, `framework/rules/proof-audits.md`, `framework/rules/records.md`, `framework/agent-actions.md`, `framework/material-format.md` and `scripts/readme.md` with that common rule, replacing duplicated Task and R capture procedures with concise pointers.
  The agent confirms that a prepared declaration, association or decision still uses the intended object and applicable content within actual authority.
  Reuse applicable current context and reread affected content after a relevant change, Task switch, interleaved work or concrete uncertainty.
  Use existing coordination, selected expected-content comparison or an equivalent guarded edit when a relevant modification could intervene before publication, including when the locator matches and reuse is unknown.
  Hold a result whose preparation input changed until the agent judges its continued applicability and any needed adjustment, preserving useful mathematics, actual review scope and effective conditions.
  The same responsibility covers Task decisions, formal R bindings, individual Task joint-parent declarations and S Task associations.
  The optional writer's `--expect` remains a locator comparison, and `--task` retains its documented allocation and type-checking scope.
  Tools report their explicit structural and selected-content checks; object continuity, mathematical applicability, review sufficiency and authority remain agent judgments.
  This adds no universal dependency capture, fingerprint, dependency register, mandatory helper, preparation record or automatic full review, version or approval after a byte change.
- Clarify [local source storage](../rules/literature.md#local-pdf-storage) in `framework/rules/literature.md` and enforce its physical boundary in `scripts/acme/core/paths.py`.
  The ordinary ignored source directory and an authorized top-level junction to private storage outside the checkout remain available for selected operations.
  A junction into the checkout is rejected before retrieval or actual source access, while public navigation keeps its logical checks.
- Apply existing ordinary path protection to the selected bibliography before its first existence check or read in `scripts/acme/intake/literature.py`, `scripts/acme/intake/acquire.py` and `scripts/acme/intake/addresses.py`.
  Cover no-op updates and the final bibliography write of a key rename, retaining the existing stale-input and publication protections.
  Report an undeclared link without exposing its target content, and document the selected access boundary in `scripts/readme.md`.

### Optional Python tool runtime

- State in `scripts/readme.md` that the optional framework commands require Python 3.12 or newer and use only the Python standard library.
  This documents the current implementation's runtime requirement rather than a particular machine's environment.
  The agent can directly invoke a suitable available interpreter without creating or activating a virtual environment or running a fixed preflight sequence.
  Research programs and document builds retain their own requirements, and reading or applying framework rules requires no Python installation.
  Keep machine-specific paths and continuing local choices in their existing local homes; this clarification adds no automatic environment installation, version-probing framework or older-interpreter compatibility path.

### Active connection recovery

- Clarify in `framework/rules/workflow.md` that an authorized network operation includes proportionate active diagnosis and handling within its actual authority, followed by completion and verification of the original operation when recovery is available under the [common recovery responsibility](../rules/workflow.md#connection-recovery).
  Align the connection and integration failure guidance in `framework/rules/identity.md` and the work-start and relevant remote-operation entrances in `framework/agent-actions.md` with that common responsibility.
  The agent selects bounded checks and adequate permitted handling from actual evidence, reuses a verified working method and obtains fresh remote facts when the operation requires them.
  Preserve existing human authority, host permission and refusal rules, certificate verification, credential confidentiality, offline instructions, operation-specific retry limits and effective Task/E conditions.
  When a concrete obstacle remains, report the actual unfinished operation and needed human action while continuing independently supported authorized work.
  Keep any necessary continuing machine-specific choice in its existing local home, without making one backend, helper or execution context a universal requirement.
  This adds no mandatory tool workflow, fixed diagnostic steps, connection register, automatic environment setup or repeated confirmation of existing authorization.
