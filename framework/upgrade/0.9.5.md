# Upgrade from 0.9.4 to 0.9.5

The target is `0.9.5`.
The preceding official tag `0.9.4` identifies [commit 07b2d24d6cf452fb600f4960d206eb903be3cf86](https://github.com/vtejdn/acme/commit/07b2d24d6cf452fb600f4960d206eb903be3cf86).
This PATCH release narrows first installation to empty project targets.
Existing 0.9.4 repositories can continue using their materials and configuration after the [ordinary in-place upgrade](../versioning.md#upgrading-an-installed-framework).

## What changed

- **Repository work starts.** The work-start instructions in `AGENTS.md`, `framework/agent-actions.md`, the related `framework/rules/` entries and `scripts/readme.md` extend the remote update to Git working repositories with a configured remote, including single-human projects.
  The main agent checks the selected project branch and completes any necessary authorized local integration before substantive work.
- **First installation.** The [installation action](../agent-actions.md#first-install-empty-target), root `readme.md`, `framework/readme.md` and `scripts/readme.md` require an empty local project root and, if present, an empty target project remote, apart from Git setup.
  A project with its own README could merge that file during first installation in 0.9.4.
  In 0.9.5 that README makes the target nonempty.
  If either already contains project work, the agent stops before source preparation, writing or merging and reports which side is nonempty to the human author.
  Even when local Git is unavailable, the agent checks any explicitly selected project remote by an authorized read-only method and postpones installation if its state cannot be confirmed.
  The workflow and identity rules give this target check priority over general project-branch integration.
- **Mathematical research coordination.** The [strategy](../rules/strategies.md#choosing-and-revising-a-route) and [workflow](../rules/workflow.md#records-review-and-handoff) rules use trial arguments to judge substantial investment, divide work by mathematical dependencies and identify gaps when assembling a complete solution.
- **On-demand strategy discovery.** The role formerly kept at the development root as `agent-S.md` now ships as [framework/rules/agent-S.md](../rules/agent-S.md), with an optional delegation entry in the [action guide](../agent-actions.md#start-or-continue-research).
  When sustained work leaves the Task stalled and no next approach is apparent, the main agent should delegate a bounded search for alternatives.
  Findings may be returned directly or in an ordinary draft marked `DoS` in its title, with `mathematics/drafts/readme.md` covering cleanup after the main agent confirms the contents and their uses have been handled.
- **Versioning and upgrade notes.** The [compatibility rule](../versioning.md#scope-and-compatibility) now asks whether an installed repository needs substantive maintenance to upgrade.
  The [upgrade-note rule](../versioning.md#contents-of-an-upgrade-note) separates shipped changes from release-specific actions.
  The 13 retained notes from `framework/upgrade/0.2.0.md` through `framework/upgrade/0.9.4.md` are shorter and retain their original upgrade paths and migration order.
- **User manuals.** The Chinese, English, French, German, Japanese and Spanish manuals under `user-manual/` identify `0.9.5` as the current framework version.

## Additional actions for this version

Ordinary synchronization suffices for existing 0.9.4 installations using the distributed files.
If local instructions refer to the development-root `agent-S.md` for this role, preserve locally authored text, change those references to `framework/rules/agent-S.md` and check that the updated instructions open the installed role.
